# Finance studies

A study is a calculation traders run over price bars: a moving average, a
rolling high or low, how unusual today's price is. pond-rs has the same
studies as pond-ts's `@pond-ts/financial`, as methods on `TimeSeries` in
the `pond_rs::financial` module. They are being added family by family;
this page lists what is built so far.

Built so far: moving averages and rolling statistics, the
moving-average family (MACD and 14 more), bands (Bollinger, Keltner and
8 more), momentum (21 studies: RSI, stochastics, CCI, true strength index
and more) and the first 8 trend studies (ADX, Aroon, SuperTrend,
parabolic SAR and more).

The results match `@pond-ts/financial` exactly, number for number. That is
checked against 2,918 cases that pond-ts itself writes out. They also match
the pandas and TA-Lib reference results pond-ts is tested against, to
within 5e-10 (133 of those 220 cases cover studies built so far).

## How every study works

- **It reads one number column**, `close` unless you name another with
  `.column("open")`.
- **It adds one column** named after the study (`sma`, `ema`, …) unless you
  name it with `.output("sma20")`. The name must not already be taken.
- **A period counts bars, not time.** A 20-bar average spans a weekend as
  easily as a minute.
- **Every row stays.** Rows before the first full window get a gap
  instead of being dropped, so the result lines up with the bars.

You describe a study with `Study::period(n)`, then chain `.column(...)` and
`.output(...)` if you need them. Calls chain too:

```rust
use pond_rs::financial::Study;
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        vec![0, minute, 2 * minute, 3 * minute],
        vec![Column::required("close", vec![10.0, 11.0, 12.0, 14.0])],
    )?;

    let out = bars
        .sma(Study::period(2))?
        .ema(Study::period(3).output("ema3"))?;

    let sma: Vec<_> = out.column("sma")?.numbers()?.iter().collect();
    assert_eq!(sma, [None, Some(10.5), Some(11.5), Some(13.0)]);
    // Gaps until 3 bars have been read; then 10 → 10.5 → 11.25 → 12.625.
    let ema: Vec<_> = out.column("ema3")?.numbers()?.iter().collect();
    assert_eq!(ema, [None, None, Some(11.25), Some(12.625)]);
    Ok(())
}
```

## Moving averages

`sma` (the plain average of the window) and `ema` (an average that weights
recent bars more, alpha `2 / (period + 1)`) have their own methods.
`moving_average(MaType, study)` gives these two and eight more, the same
ten pond-ts offers. Its output is called `ma`.

| `MaType` | What it is                                                                        |
| -------- | --------------------------------------------------------------------------------- |
| `Sma`    | Plain average (the same numbers as `sma`)                                         |
| `Ema`    | Exponential average (the same numbers as `ema`)                                   |
| `Wma`    | Weighted 1, 2, …, period, newest bar heaviest                                     |
| `Smma`   | Wilder's smoothing, the average RSI and ATR use                                   |
| `Dema`   | Double exponential: `2 × ema − ema of the ema`, which lags less                   |
| `Tema`   | Triple exponential, lags less again                                               |
| `Trima`  | Triangular: an average of an average, so the middle of the window counts the most |
| `Hull`   | Hull: built from weighted averages to cut lag                                     |
| `Kama`   | Kaufman's adaptive average: fast when prices trend, slow when they chop           |
| `Zlema`  | Zero-lag exponential: an EMA of the price pushed forward by its own recent change |

`MaType::parse("hull")` turns pond-ts's name for a type into the `MaType`,
which helps when the type comes from a setting or a file.

```rust
use pond_rs::financial::{MaType, Study};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        vec![0, minute, 2 * minute, 3 * minute],
        vec![Column::required("close", vec![10.0, 11.0, 12.0, 14.0])],
    )?;

    let wma = bars.moving_average(MaType::Wma, Study::period(3))?;
    // Weights 1, 2, 3 on 11, 12, 14: (11 + 24 + 42) / 6.
    assert_eq!(wma.column("ma")?.numbers()?.get(3), Some(77.0 / 6.0));

    let kind = MaType::parse("hull")?;
    assert_eq!(kind, MaType::Hull);
    assert!(MaType::parse("hma").is_err()); // the error lists the ten names
    Ok(())
}
```

## Rolling statistics and the z-score

| Call                           | Output                      | What each row gets                                                        |
| ------------------------------ | --------------------------- | ------------------------------------------------------------------------- |
| `rolling_stdev(study)`         | `stdev`                     | The spread of the window (population standard deviation)                  |
| `rolling_min(study)`           | `min`                       | The lowest value in the window                                            |
| `rolling_max(study)`           | `max`                       | The highest value in the window                                           |
| `rolling_percentile(q, study)` | `p` and `q` (`p90`, `p2.5`) | The `q`th percentile, 0 to 100, in between ranks drawn as a straight line |
| `z_score(study)`               | `zscore`                    | How many standard deviations this bar sits from its window's average      |

A z-score has no answer when the window is flat (no spread), so that row
gets a gap.

```rust
use pond_rs::financial::Study;
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        (0..5).map(|i| i * minute).collect(),
        vec![Column::required("close", vec![5.0, 5.0, 3.0, 7.0, 7.0])],
    )?;

    let out = bars
        .rolling_min(Study::period(3))?
        .rolling_max(Study::period(3))?
        .rolling_percentile(50.0, Study::period(3))?
        .z_score(Study::period(2))?;

    let low: Vec<_> = out.column("min")?.numbers()?.iter().collect();
    assert_eq!(low, [None, None, Some(3.0), Some(3.0), Some(3.0)]);
    let high: Vec<_> = out.column("max")?.numbers()?.iter().collect();
    assert_eq!(high, [None, None, Some(5.0), Some(7.0), Some(7.0)]);
    assert_eq!(out.column("p50")?.numbers()?.get(2), Some(5.0));

    // 5, 5 is flat: no z-score. 3 after 5 is one deviation below.
    let z: Vec<_> = out.column("zscore")?.numbers()?.iter().collect();
    assert_eq!(z, [None, None, Some(-1.0), Some(1.0), None]);
    Ok(())
}
```

## Studies with more settings

Studies with only a period take a `Study`. The rest take an options value
named after the study: `Macd`, `Bollinger`, `Stochastic` and so on.

- **`::default()` gives pond-ts's defaults.** `Macd::default()` is fast 12,
  slow 26, signal 9. Each setting has a setter of the same name:
  `Macd::default().fast(5).signal(5)`.
- **`Bollinger` and `Envelope` have no default period** in pond-ts either,
  so they start from `new(period)`: `Bollinger::new(20).std_dev(2.5)`.
- **Studies that write several columns** take a `prefix` instead of an
  `output`. `bollinger` writes `bbMiddle`, `bbUpper` and `bbLower`;
  `.prefix("wide")` makes them `wideMiddle`, `wideUpper` and `wideLower`.
  The names are pond-ts's, camel case and all, so results line up with
  pond-ts output.
- **Studies of whole price bars** read `high`, `low`, `close` (and `open`
  where they need it) by those names, with one setter per column to read
  another: `Keltner::default().high("ask_high")`.

```rust
use pond_rs::financial::{Bollinger, Donchian};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        vec![0, minute, 2 * minute],
        vec![
            Column::required("hi", vec![11.0, 13.0, 12.0]),
            Column::required("low", vec![9.0, 11.0, 8.0]),
            Column::required("close", vec![10.0, 12.0, 9.0]),
        ],
    )?;

    // A 2-bar average with bands 2 standard deviations either side.
    let bb = bars.bollinger(Bollinger::new(2))?;
    let names: Vec<&str> = bb.columns().iter().map(|c| c.name()).collect();
    assert_eq!(names, ["hi", "low", "close", "bbMiddle", "bbUpper", "bbLower"]);
    // Bar 2's window is 10 and 12: average 11, spread 1.
    assert_eq!(bb.column("bbMiddle")?.numbers()?.get(1), Some(11.0));
    assert_eq!(bb.column("bbUpper")?.numbers()?.get(1), Some(13.0));
    assert_eq!(bb.column("bbLower")?.numbers()?.get(1), Some(9.0));

    // The high prices are in "hi" here, not "high".
    let dc = bars.donchian(Donchian::default().period(2).high("hi").prefix("ch"))?;
    assert_eq!(dc.column("chUpper")?.numbers()?.get(2), Some(13.0));
    assert_eq!(dc.column("chLower")?.numbers()?.get(2), Some(8.0));
    assert_eq!(dc.column("chMiddle")?.numbers()?.get(2), Some(10.5));
    Ok(())
}
```

## More moving-average studies

Studies built from moving averages. Where a study lets you pick the kind
of average, the setter is `ma(MaType)` (pond-ts's `type` or `maType`).

| Call                                                 | Writes                               | What it shows                                                                                                              |
| ---------------------------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `macd(Macd)`                                         | `macdLine`, `macdSignal`, `macdHist` | The fast EMA minus the slow one, an EMA of that, and the gap between the two                                               |
| `price_oscillator(PriceOscillator)`                  | `priceOsc`                           | The gap between a fast and a slow average, as a percent of the slow one, or in price with `mode(OscillatorMode::Absolute)` |
| `moving_average_cross(MovingAverageCross)`           | `maCross`                            | `1` on the bar the fast average moves above the slow one, `-1` when it moves below, `0` otherwise                          |
| `moving_average_deviation(MaType, Study)`            | `maDev`                              | The price minus its average, in price                                                                                      |
| `disparity_index(MaType, Study)`                     | `disparity`                          | The same as a percent of the average                                                                                       |
| `detrended_price_oscillator(MaType, Study)`          | `dpo`                                | The price minus the average from half a period earlier, which takes out the trend                                          |
| `guppy(Guppy)`                                       | `gmmaS3` … `gmmaL60`                 | Twelve EMAs: six short (3 to 15 bars), six long (30 to 60)                                                                 |
| `rainbow(Rainbow)`                                   | `rainbow1` … `rainbow10`             | Ten averages, each of the one before                                                                                       |
| `rainbow_oscillator(RainbowOscillator)`              | `rbo`, `rboUpper`, `rboLower`        | The price against the rainbow's average, scaled by the recent range                                                        |
| `trix(Trix)`                                         | `trix`, `trixSignal`                 | The one-bar percent change of a triple EMA, and an EMA of that                                                             |
| `schaff_trend_cycle(SchaffTrendCycle)`               | `stc`                                | A 0 to 100 cycle built from the MACD line                                                                                  |
| `coppock(Coppock)`                                   | `coppock`                            | A weighted average of two percent changes                                                                                  |
| `kst(Kst)`                                           | `kst`, `kstSignal`                   | Pring's Know Sure Thing: four smoothed percent changes, weighted                                                           |
| `special_k(SpecialK)`                                | `specialK`                           | Pring's Special K: twelve of them, reaching back 530 bars, so it starts about 724 bars in                                  |
| `price_momentum_oscillator(PriceMomentumOscillator)` | `pmo`, `pmoSignal`                   | DecisionPoint's PMO: a doubly smoothed percent change                                                                      |

Each column starts as soon as it can. At the defaults, `macdLine` starts
at bar 26 (row 25) and the signal and histogram at bar 34 (row 33).

```rust
use pond_rs::financial::{Macd, MaType, Study};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let close: Vec<f64> = (0..40).map(|i| 100.0 + (i as f64 / 3.0).sin()).collect();
    let bars = TimeSeries::new(
        "bars",
        (0..40).map(|i| i * 60_000).collect(),
        vec![Column::required("close", close)],
    )?;

    let out = bars
        .macd(Macd::default())?
        .moving_average_deviation(MaType::Sma, Study::period(20))?;

    let line = out.column("macdLine")?.numbers()?;
    assert_eq!((line.get(24), line.get(25).is_some()), (None, true));
    let signal = out.column("macdSignal")?.numbers()?;
    assert_eq!((signal.get(32), signal.get(33).is_some()), (None, true));
    assert!(out.column("maDev")?.numbers()?.get(19).is_some());
    Ok(())
}
```

## Bands

Lines drawn above and below the price. Most write a middle, an upper and
a lower column.

| Call                                      | Writes                                    | The bands                                                                                |
| ----------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| `bollinger(Bollinger::new(period))`       | `bbMiddle`, `bbUpper`, `bbLower`          | An average, with bands `std_dev` standard deviations away (default 2)                    |
| `bollinger_bandwidth(BollingerBandwidth)` | `bbWidth`                                 | How far apart the Bollinger bands are, as a percent of the middle                        |
| `bollinger_percent_b(BollingerPercentB)`  | `percentB`                                | Where the price sits between the bands: 0 at the lower, 1 at the upper                   |
| `keltner(Keltner)`                        | `kcMiddle`, `kcUpper`, `kcLower`          | An EMA of the typical price `(high + low + close) / 3`, bands 2 average true ranges away |
| `starc_bands(StarcBands)`                 | `starcMiddle`, `starcUpper`, `starcLower` | A simple average of the close, bands 2 average true ranges away                          |
| `atr_bands(AtrBands)`                     | `atrbUpper`, `atrbLower`                  | Bands 2 average true ranges either side of the close                                     |
| `donchian(Donchian)`                      | `dcUpper`, `dcLower`, `dcMiddle`          | The highest high and lowest low of the last 20 bars, and halfway between                 |
| `high_low_bands(HighLowBands)`            | `hlbMiddle`, `hlbUpper`, `hlbLower`       | A triangular average of the median price `(high + low) / 2`, bands 1% either side        |
| `prime_number_bands(PrimeNumberBands)`    | `pnbUpper`, `pnbLower`                    | The nearest prime at or above each high, and at or below each low                        |
| `envelope(Envelope::new(period))`         | `envMiddle`, `envUpper`, `envLower`       | An average, with bands 2.5% either side                                                  |

The **true range** of a bar is how far the price moved, counting a jump
from the last close: the largest of high minus low, high minus the last
close, and the last close minus low. Its average uses Wilder's smoothing,
which never recovers from a gap: after a missing bar inside the data, the
bands that use it stay empty. A gap at the start only delays them.

Prime number bands work on whole numbers up to 2^53 − 1 (the largest whole
number a 64-bit float holds exactly); a price below 2 or above that gets a
gap.

## Momentum

How fast and how far the price is moving.

| Call                                                 | Writes                   | What it shows                                                                                                     |
| ---------------------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `rsi(Study)`                                         | `rsi`                    | Relative strength index, 0 to 100: recent rises against recent falls (pond-ts's period: 14)                       |
| `chande_momentum(Study)`                             | `cmo`                    | Chande's version, −100 to 100: rises minus falls over their total (period 14)                                     |
| `momentum(Study)`                                    | `momentum`               | The price minus the price `period` bars back (period 10)                                                          |
| `percent_change(PercentChange)`                      | `pctChange`              | The change from `periods` bars back, as a percent                                                                 |
| `stochastic(Stochastic)`                             | `stochK`, `stochD`       | Where the close sits in the recent high-low range, 0 to 100, smoothed (%K), and an average of that (%D)           |
| `stochastic_momentum_index(StochasticMomentumIndex)` | `smi`, `smiSignal`       | How far the close is from the middle of the recent range, smoothed twice                                          |
| `stochastic_rsi(StochasticRsi)`                      | `stochRsiK`, `stochRsiD` | The stochastic of the RSI instead of the price                                                                    |
| `williams_r(WilliamsR)`                              | `williamsR`              | Williams %R: where the close sits in the recent range, from −100 (the low) to 0 (the high)                        |
| `intraday_momentum_index(IntradayMomentumIndex)`     | `imi`                    | The RSI idea on each bar's body (close minus open)                                                                |
| `awesome_oscillator(AwesomeOscillator)`              | `ao`                     | A 5-bar average of the median price minus a 34-bar one                                                            |
| `ultimate_oscillator(UltimateOscillator)`            | `uo`                     | Buying pressure over three windows (7, 14 and 28 bars), weighted 4, 2 and 1                                       |
| `commodity_channel_index(CommodityChannelIndex)`     | `cci`                    | Commodity channel index: how far the typical price is from its 20-bar average, in units of its usual distance     |
| `fisher_transform(FisherTransform)`                  | `fisher`, `fisherSignal` | The median price's place in its 10-bar range, stretched so turning points stand out; the signal is the bar before |
| `psychological_line(Study)`                          | `psy`                    | The percent of the last `period` bars that closed higher than the bar before (period 12)                          |
| `pretty_good_oscillator(PrettyGoodOscillator)`       | `pgo`                    | How far the close is from its 14-bar average, in average true ranges                                              |
| `prime_number_oscillator(PrimeNumberOscillator)`     | `pno`                    | The price minus the nearest prime (the lower one on a tie)                                                        |
| `qstick(Qstick)`                                     | `qstick`                 | An 8-bar average of each bar's body (close minus open)                                                            |
| `relative_vigor_index(RelativeVigorIndex)`           | `rvi`, `rviSignal`       | Bar bodies against bar ranges over 10 bars: closing near the high means buyers are strong                         |
| `center_of_gravity(Study)`                           | `cog`                    | Where the window's values balance, in bars (period 10)                                                            |
| `chande_forecast_oscillator(Study)`                  | `cfo`                    | How far the price is from a straight-line fit's forecast, as a percent (period 14, at least 2)                    |
| `true_strength_index(TrueStrengthIndex)`             | `tsi`, `tsiSignal`       | Each bar's change over its size, both smoothed twice, so −100 to 100                                              |

`rsi` is 100 when nothing fell in the window, and a gap when nothing moved.

The Fisher transform takes a logarithm. Rust's own `ln` gives a slightly
different last digit from JavaScript's `Math.log` on about 2% of inputs,
so pond-rs carries a copy of the routine V8 uses (fdlibm's), which matched
Node on all 2 million values tried. That is what keeps `fisher_transform`
exactly equal to pond-ts.

```rust
use pond_rs::financial::{Qstick, Study};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        (0..4).map(|i| i * minute).collect(),
        vec![
            Column::required("open", vec![10.0, 10.0, 12.0, 12.0]),
            Column::required("close", vec![11.0, 12.0, 11.0, 13.0]),
        ],
    )?;

    let out = bars
        .qstick(Qstick::default().period(2))?
        .psychological_line(Study::period(2))?;

    // Bodies are 1, 2, -1 and 1; qstick averages each pair.
    let q: Vec<_> = out.column("qstick")?.numbers()?.iter().collect();
    assert_eq!(q, [None, Some(1.5), Some(0.5), Some(0.0)]);
    // Of the last two bars, one closed higher than the bar before.
    let psy: Vec<_> = out.column("psy")?.numbers()?.iter().collect();
    assert_eq!(psy, [None, None, Some(50.0), Some(50.0)]);
    Ok(())
}
```

```rust
use pond_rs::financial::{Study, WilliamsR};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        (0..4).map(|i| i * minute).collect(),
        vec![
            Column::required("high", vec![11.0, 12.0, 13.0, 12.0]),
            Column::required("low", vec![9.0, 10.0, 11.0, 10.0]),
            Column::required("close", vec![10.0, 11.0, 12.0, 11.0]),
        ],
    )?;

    let out = bars
        .rsi(Study::period(2))?
        .momentum(Study::period(1))?
        .williams_r(WilliamsR::default().period(2))?;

    // Two rises: nothing fell, so 100. Then one fall: rises and falls even.
    let rsi: Vec<_> = out.column("rsi")?.numbers()?.iter().collect();
    assert_eq!(rsi, [None, None, Some(100.0), Some(50.0)]);
    let momentum: Vec<_> = out.column("momentum")?.numbers()?.iter().collect();
    assert_eq!(momentum, [None, Some(1.0), Some(1.0), Some(-1.0)]);

    // Last bar: the range over 2 bars is 10 to 13 and the close is 11,
    // two thirds of the way down from the high.
    let w = out.column("williamsR")?.numbers()?.get(3).unwrap();
    assert!((w - -200.0 / 3.0).abs() < 1e-12);
    Ok(())
}
```

## Trend

Whether the price is trending, which way, and where a trader might put a
stop.

| Call                                        | Writes                                                  | What it shows                                                                                                 |
| ------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `directional_movement(DirectionalMovement)` | `dmiPlusDi`, `dmiMinusDi`, `dmiDx`, `dmiAdx`, `dmiAdxr` | Wilder's system: the up and down moves (+DI, −DI), and ADX, how strong the trend is whichever way it goes     |
| `aroon(Aroon)`                              | `aroonUp`, `aroonDown`, `aroonOsc`                      | How recently the 25-bar high and low happened: 100 for this bar, 0 for 25 bars back                           |
| `vortex(Vortex)`                            | `viPlus`, `viMinus`                                     | Upward against downward movement over 14 bars                                                                 |
| `vertical_horizontal_filter(Study)`         | `vhf`                                                   | The window's range over the sum of its bar-to-bar moves: high when trending, low when choppy (period 28)      |
| `random_walk_index(RandomWalkIndex)`        | `rwiHigh`, `rwiLow`                                     | How much further the price went than a random walk would, up and down, over 2 to 14 bars                      |
| `super_trend(SuperTrend)`                   | `st`, `stTrend`                                         | A line 3 average true ranges below the price in an up trend (above in a down trend); `stTrend` is `1` or `-1` |
| `parabolic_sar(ParabolicSar)`               | `psar`, `psarTrend`                                     | Wilder's stop-and-reverse: a stop that speeds up toward the price, and flips side when the price crosses it   |
| `atr_trailing_stop(AtrTrailingStop)`        | `ats`, `atsTrend`                                       | A stop 3 average true ranges from the close that only moves toward the price, until the price crosses it      |

The random walk index needs a period of at least 2, and the parabolic
SAR's `max_step` must be at least its `step`.

SuperTrend, the SAR and the ATR stop each work bar by bar. After a missing
bar, the SAR starts again with the next stretch of bars. SuperTrend and
the ATR stop use the average true range, so as with the bands, a missing
bar in the middle of the data leaves them empty from there on.

```rust
use pond_rs::financial::{Aroon, SuperTrend};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        (0..3).map(|i| i * minute).collect(),
        vec![
            Column::required("high", vec![2.0, 3.0, 4.0]),
            Column::required("low", vec![1.0, 2.0, 3.0]),
            Column::required("close", vec![1.5, 2.5, 3.5]),
        ],
    )?;

    let out = bars.aroon(Aroon::default().period(2))?;
    // The highest high is this bar (100); the lowest low was 2 bars back (0).
    assert_eq!(out.column("aroonUp")?.numbers()?.get(2), Some(100.0));
    assert_eq!(out.column("aroonDown")?.numbers()?.get(2), Some(0.0));
    assert_eq!(out.column("aroonOsc")?.numbers()?.get(2), Some(100.0));

    let st = bars.super_trend(SuperTrend::default().period(2))?;
    let names: Vec<&str> = st.columns().iter().map(|c| c.name()).collect();
    assert_eq!(names, ["high", "low", "close", "st", "stTrend"]);
    Ok(())
}
```

## Gaps in the prices

A gap in the source column never shifts the rows. What a study does with
it depends on the study, as in pond-ts:

- `sma`, `rolling_stdev`, `rolling_min`, `rolling_max` and
  `rolling_percentile` skip it and use the window's other values. A window
  of only gaps gives a gap.
- `ema` gives the gap row a gap and carries on from where it was. `Dema`,
  `Tema` and `Zlema` do the same.
- `Wma`, `Trima` and `Hull` give a gap while the window holds one.
- `Smma` and `Kama` start after gaps at the beginning, but a gap later on
  turns every value after it into a gap.

```rust
use pond_rs::financial::{MaType, Study};
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        (0..4).map(|i| i * minute).collect(),
        vec![Column::optional(
            "close",
            vec![Some(10.0), None, Some(12.0), Some(14.0)],
        )],
    )?;

    let sma = bars.sma(Study::period(2))?;
    let got: Vec<_> = sma.column("sma")?.numbers()?.iter().collect();
    // The gap is skipped: 10 alone, then 12 alone, then 12 and 14.
    assert_eq!(got, [None, Some(10.0), Some(12.0), Some(13.0)]);

    let wma = bars.moving_average(MaType::Wma, Study::period(2))?;
    let got: Vec<_> = wma.column("ma")?.numbers()?.iter().collect();
    // A gap while the window holds the gap.
    assert_eq!(got, [None, None, None, Some((12.0 + 2.0 * 14.0) / 3.0)]);
    Ok(())
}
```

## Several symbols

A study runs down the whole series. For a series holding several symbols,
split it with `partition_by` and run the study on each symbol with `apply`
(see [Partitions](./partitions)):

```rust
use pond_rs::financial::Study;
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let bars = TimeSeries::new(
        "bars",
        vec![0, 0, minute, minute],
        vec![
            Column::required("symbol", vec!["AAA", "BBB", "AAA", "BBB"]),
            Column::required("close", vec![10.0, 200.0, 12.0, 210.0]),
        ],
    )?;

    let out = bars
        .partition_by(&["symbol"])?
        .apply(|one| one.sma(Study::period(2)))?;
    let rows: Vec<_> = out
        .rows()
        .map(|r| (r.string("symbol").unwrap(), r.number("sma").unwrap()))
        .collect();
    // AAA's average never sees BBB's prices.
    assert!(rows.contains(&(Some("AAA"), Some(11.0))));
    assert!(rows.contains(&(Some("BBB"), Some(205.0))));
    Ok(())
}
```

## Mistakes are errors

pond-rs refuses a study it cannot run, with a message naming the call and
the problem:

- a period of 0;
- an output name that is already a column (or the key);
- a source column that does not exist, or is not numbers (for studies of
  price bars, each of the high, low, close or open columns it reads);
- a Bollinger `std_dev`, band `multiplier` or `percent` that is not a finite
  number above zero;
- for `macd` and `stochastic_rsi`, a series that already has a column
  named `__macdLine__` or `__stochRsiRsi__`. pond-ts writes its working
  values there, so it refuses them too.

The last one differs from pond-ts. pond-ts gives a column of all gaps for
a misspelled or text source column, so a typo looks like "no data"
(`rolling_min`, `rolling_max` and `rolling_percentile` do throw on a
missing column). That is logged as a pond-ts issue, [PND-STUDYSRC].
pond-rs also refuses an exact decimal column, which pond-ts has no kind
for. A period is a whole number (`usize`), so the negative and fractional
periods pond-ts has to check for cannot be written.

```rust
use pond_rs::financial::Study;
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let bars = TimeSeries::new(
        "bars",
        vec![0, 60_000],
        vec![
            Column::required("close", vec![10.0, 11.0]),
            Column::required("venue", vec!["X", "Y"]),
        ],
    )?;

    assert!(bars.sma(Study::period(0)).is_err());
    assert!(bars.sma(Study::period(2).column("clsoe")).is_err());
    assert!(bars.sma(Study::period(2).column("venue")).is_err());
    assert!(bars.sma(Study::period(2).output("close")).is_err());
    Ok(())
}
```

The machine is a shared virtual machine with four cores, and single runs
move by up to a third, so read the ratios as rough. `atr_bands` gains the
least because its average true range is one chain where each row needs
the one before, which pond-ts pays for too.

**Why some use several cores and some don't.** The window studies (`sma`,
`rolling_stdev`, `rolling_min` / `rolling_max`, and the `Wma`, `Trima` and
`Hull` averages) cut the bars into long stretches and work on them at the
same time. The answer is still the same to the last bit: each stretch
starts where a running sum is rebuilt from scratch anyway, so it does
exactly what one pass would. `ema`, `Smma`, `Dema`, `Tema`, `Zlema`,
`Kama` and the z-score cannot be cut up, because each row needs the
answer for the row before it; changing the order of the sums would also
stop them matching pond-ts exactly. The percentile keeps each window
sorted, which makes it the slowest.

Most of the first version's time was spent getting fresh memory, not on
the maths. A study now reads the price column where it is instead of
copying it, and the result shares the input's times instead of copying
them.
