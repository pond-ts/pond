# Operations

Every operation takes a series and returns a new one. Column names are
plain strings, durations are short strings like `"500ms"`, `"30s"`, `"5m"`,
`"1h"` or `"1d"`, and every call returns a `Result`.

## Rolling windows

`rolling(window, aggs)` looks back from each row: for a row at time `t` it
reduces the rows with time in `(t - window, t]`. The result has the same
rows and keys as the input, and **only the columns you ask for**: one per
`Agg`. Every other column is dropped, as in pond-ts. To keep one, ask for it,
for example `Agg::of("host", Reducer::Last)` (the row's own value, since the
window ends at that row).

```rust
use pond_rs::{Agg, Column, Reducer, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let s = TimeSeries::new(
        "cpu",
        vec![0, 1_000, 2_000, 3_000],
        vec![Column::optional(
            "load",
            vec![Some(1.0), None, Some(3.0), Some(5.0)],
        )],
    )?;

    let r = s.rolling(
        "2s",
        &[
            Agg::new("load_avg", "load", Reducer::Avg),
            Agg::new("load_n", "load", Reducer::Count),
        ],
    )?;

    // At 3s the window (1s, 3s] holds 3.0 and 5.0; the gap at 1s is skipped.
    assert_eq!(r.column("load_avg")?.numbers()?.get(3), Some(4.0));
    assert_eq!(r.column("load_n")?.numbers()?.get(3), Some(2.0));
    // At 1s the window (-1s, 1s] holds only 1.0.
    assert_eq!(r.column("load_avg")?.numbers()?.get(1), Some(1.0));

    // Only the asked-for columns come out; `load` itself is gone.
    assert!(r.column("load").is_err());
    let names: Vec<&str> = r.columns().iter().map(|c| c.name()).collect();
    assert_eq!(names, ["load_avg", "load_n"]);
    Ok(())
}
```

`Agg::new(output, source, reducer)` names the output column.
`Agg::of(source, reducer)` reuses the source's name, like pond-ts's
`{ load: 'avg' }`.

## Buckets: `aggregate`

`aggregate(sequence, aggs)` puts each row in the bucket that holds it
(`begin <= t < end`) and reduces each bucket to one row. Buckets run from
the one holding the first row to the one holding the last, **including
empty buckets in between**, so a missing hour shows up as a row rather than
disappearing. An empty bucket gives `count` 0, `sum` 0 and a gap for every
other reducer.

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    // Readings in minutes 0 and 2; nothing in minute 1.
    let s = TimeSeries::new(
        "req",
        vec![0, 30_000, 2 * minute],
        vec![Column::required("ms", vec![120.0, 80.0, 200.0])],
    )?;

    let per_minute = s.aggregate(
        &Sequence::every("1m")?,
        &[
            Agg::new("n", "ms", Reducer::Count),
            Agg::new("avg", "ms", Reducer::Avg),
            Agg::new("p95", "ms", Reducer::Percentile(95.0)),
        ],
    )?;

    assert_eq!(per_minute.len(), 3); // minute 1 is there, empty
    let n: Vec<_> = per_minute.column("n")?.numbers()?.iter().collect();
    let avg: Vec<_> = per_minute.column("avg")?.numbers()?.iter().collect();
    assert_eq!(n, [Some(2.0), Some(0.0), Some(1.0)]);
    assert_eq!(avg, [Some(100.0), None, Some(200.0)]);
    Ok(())
}
```

### Fixed-length buckets

`Sequence::every("15m")` gives 15-minute buckets lined up with Unix time 0
(so on :00, :15, :30, :45 in UTC). `Sequence::every_ms(n)` takes
milliseconds. `.with_anchor(t)` shifts the grid so a bucket starts at `t`.

### Calendar buckets

`Sequence::calendar(unit, time_zone)` gives calendar buckets in an IANA
time zone: `"day"`, `"week"`, `"month"`, `"quarter"` or `"year"`. A New York
day is 23 hours on the day the clocks go forward and 25 on the day they go
back; months have their real lengths. Weeks start on Monday;
`.with_week_start(7)` starts them on Sunday (ISO numbering, 1 = Monday).

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries, parse_time_in};

fn main() -> Result<(), pond_rs::PondError> {
    let hour = 3_600_000_i64;
    // Hourly sales for 50 hours from Saturday 24 October 2026, 00:00 in
    // London (still summer time, so 23:00 UTC the day before).
    let start = parse_time_in("2026-10-24", "Europe/London")?;
    let times: Vec<i64> = (0..50).map(|h| start + h * hour).collect();
    let s = TimeSeries::new(
        "sales",
        times,
        vec![Column::required("units", vec![1.0; 50])],
    )?;

    let days = s.aggregate(
        &Sequence::calendar("day", "Europe/London")?,
        &[Agg::new("units", "units", Reducer::Sum)],
    )?;
    // UK clocks go back on Sunday 25 October, so that day has 25 hours.
    let sums: Vec<_> = days.column("units")?.numbers()?.iter().collect();
    assert_eq!(sums, [Some(24.0), Some(25.0), Some(1.0)]);
    Ok(())
}
```

Time-zone rules come from the time-zone database built into pond-rs
(`pond_rs::tzdb_version()` says which release). pond-ts uses the one in its
JavaScript engine; if the two releases disagree about a zone's history, the
buckets will too.

### Reducers

| Reducer                   | Gives                                             | Also works on               |
| ------------------------- | ------------------------------------------------- | --------------------------- |
| `Count`                   | how many values (gaps not counted)                | every kind                  |
| `Sum`                     | total; 0 when there are no values                 | decimals (exact)            |
| `Avg`                     | mean                                              | decimals (as a number)      |
| `Min`, `Max`              | smallest, largest                                 | decimals (exact)            |
| `First`, `Last`           | first or last value in the window or bucket       | every kind (keeps the kind) |
| `Median`, `Percentile(q)` | the middle value, or the `q`th percentile (0–100) | decimals (as a number)      |
| `Stdev`                   | standard deviation (population, divides by n)     | decimals (as a number)      |

On text and true/false columns only `Count`, `First` and `Last` are
allowed; anything else is an error naming the column. `Reducer::parse("p95")`
and `"avg".parse::<Reducer>()` turn pond-ts's reducer names into a
`Reducer`.

## Row by row

These compare each row with the one before it, or carry a running value
down the column. They take a list of columns; other columns pass through
unchanged.

| Call                            | Each row gets                                          |
| ------------------------------- | ------------------------------------------------------ |
| `diff(&cols, first)`            | value minus the previous row's                         |
| `rate(&cols, first)`            | change per second of key time                          |
| `pct_change(&cols, first)`      | change as a fraction of the previous value (not × 100) |
| `shift(&cols, n)`               | the value from `n` rows up (negative `n`: rows down)   |
| `cumulative(&[(col, reducer)])` | running `Sum`, `Min`, `Max` or `Count`                 |
| `cumulative_with(col, closure)` | a running value of your own                            |
| `fill(&[(col, Fill)], &limits)` | gaps filled by a rule                                  |

`first` is `FirstRow::Keep` (the first row stays, with a gap) or
`FirstRow::Drop` (it is removed). "Previous row" means the row directly
above, not the last row with a value, so a gap on either side gives a gap.

```rust
use pond_rs::{Column, FirstRow, Reducer, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    // A counter read every 10 seconds; one reading is missing.
    let s = TimeSeries::new(
        "bytes",
        vec![0, 10_000, 20_000, 30_000],
        vec![Column::optional(
            "total",
            vec![Some(100.0), Some(400.0), None, Some(1_000.0)],
        )],
    )?;

    let per_second = s.rate(&["total"], FirstRow::Keep)?;
    let got: Vec<_> = per_second.column("total")?.numbers()?.iter().collect();
    assert_eq!(got, [None, Some(30.0), None, None]);

    let running = s.cumulative(&[("total", Reducer::Max)])?;
    let got: Vec<_> = running.column("total")?.numbers()?.iter().collect();
    assert_eq!(got, [Some(100.0), Some(400.0), Some(400.0), Some(1_000.0)]);
    Ok(())
}
```

### Filling gaps

`Fill` says how: `Hold` (carry the last value forward), `Bfill` (take the
next value), `Linear` (a straight line by time between the values either
side; numbers only), `Zero`, or `Value(..)` (a fixed value of the column's
kind). `FillLimits` caps which runs of gaps get filled; a run that is too
long is left entirely as it was, never half filled.

```rust
use pond_rs::{Column, Fill, FillLimits, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let minute = 60_000;
    let times: Vec<i64> = (0..7).map(|m| m * minute).collect();
    let s = TimeSeries::new(
        "temp",
        times,
        vec![Column::optional(
            "c",
            vec![
                Some(20.0),
                None,
                Some(22.0), // a 1-row gap
                None,
                None,
                None,
                Some(30.0), // a 3-row gap
            ],
        )],
    )?;

    // Fill straight lines, but only across gaps of at most 2 minutes
    // (measured from the value before to the value after).
    let filled =
        s.fill(&[("c", Fill::Linear)], &FillLimits::none().max_gap("2m"))?;
    let got: Vec<_> = filled.column("c")?.numbers()?.iter().collect();
    assert_eq!(
        got,
        [
            Some(20.0),
            Some(21.0),
            Some(22.0),
            None,
            None,
            None,
            Some(30.0)
        ]
    );
    Ok(())
}
```

`fill_all(Fill::Hold, &limits)` applies one rule to every column.

## Picking rows

`slice(range)` picks rows by position, with negative positions counting
from the end, as JavaScript's `slice` does. `filter(closure)` keeps the rows
for which the closure returns `Ok(true)`; the closure gets a `Row` and can
use `?` on its lookups.

```rust
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let s = TimeSeries::new(
        "cpu",
        vec![0, 1_000, 2_000, 3_000],
        vec![
            Column::required("host", vec!["a", "b", "a", "b"]),
            Column::optional(
                "load",
                vec![Some(0.2), None, Some(0.9), Some(0.7)],
            ),
        ],
    )?;

    assert_eq!(s.slice(-2..).key().begin(), &[2_000, 3_000]); // the last two
    assert_eq!(s.slice(1..3).len(), 2);

    let busy = s.filter(|r| Ok(r.number("load")?.is_some_and(|v| v > 0.5)))?;
    assert_eq!(busy.key().begin(), &[2_000, 3_000]);

    // Faster for big series: look the column up once, then index by row.
    let host = s.column("host")?.strings()?;
    let only_a = s.filter(|r| Ok(host.get(r.index()) == Some("a")))?;
    assert_eq!(only_a.len(), 2);
    Ok(())
}
```

`tail("60m")` keeps the rows in the last stretch of time: those that start
**after** the last row's time minus 60 minutes, so a row exactly 60 minutes
before the last one is left out. `first()` and `last()` give the first and
last row, or `None` for an empty series.

```rust
use pond_rs::{Column, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let min = 60_000;
    let s = TimeSeries::new(
        "price",
        vec![0, 30 * min, 60 * min, 90 * min],
        vec![Column::required("close", vec![10.0, 12.0, 14.0, 13.0])],
    )?;

    // The last row is at 90 minutes; the last hour is after 30 minutes.
    let hour = s.tail("60m")?;
    assert_eq!(hour.key().begin(), &[60 * min, 90 * min]);

    let last = s.last().expect("not empty");
    assert_eq!(last.begin(), 90 * min);
    assert_eq!(last.number("close")?, Some(13.0));
    Ok(())
}
```

## One row for the whole series: `reduce`

`reduce(&aggs)` boils the whole series down to one value per `Agg`, with
the same reducers and rules as `aggregate` (as if the whole series were one
bucket). It returns a `Reduced`, which you read by output name:
`number`, `string`, `boolean` and `decimal` check the kind, `get` gives a
`Value` of any kind. A gap is `Ok(None)`; an empty series gives `count` 0,
`sum` 0 and gaps for the rest.

With `tail`, this answers "what are things like right now" without
computing a rolling window at every row of the history:

```rust
use pond_rs::{Agg, Column, Reducer, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let min = 60_000;
    let s = TimeSeries::new(
        "price",
        vec![0, 30 * min, 60 * min, 90 * min],
        vec![
            Column::required("symbol", vec!["A", "A", "A", "A"]),
            Column::required("close", vec![10.0, 12.0, 14.0, 13.0]),
        ],
    )?;

    let now = s.tail("60m")?.reduce(&[
        Agg::new("mean", "close", Reducer::Avg),
        Agg::new("close", "close", Reducer::Last),
        Agg::new("symbol", "symbol", Reducer::First),
    ])?;
    assert_eq!(now.number("mean")?, Some(13.5)); // (14 + 13) / 2
    assert_eq!(now.number("close")?, Some(13.0));
    assert_eq!(now.string("symbol")?, Some("A"));
    assert!(now.number("symbol").is_err()); // text, not a number
    Ok(())
}
```

## Finding rows

These look up one row, or answer a yes/no question, without building a new
series. Each is the pond-ts call of the same name.

| Call                         | Gives                                                                   |
| ---------------------------- | ----------------------------------------------------------------------- |
| `at(i)`                      | the row at position `i`; `-1` is the last row. `None` past either end   |
| `bisect(key)`                | the position where `key` would go: the first row not before it          |
| `includes_key(key)`          | whether a row has exactly that key                                      |
| `at_or_before(key)`          | the row with exactly that key, else the last row before it              |
| `at_or_after(key)`           | the first row not before the key                                        |
| `nearest(key)`               | the row whose start is closest; a tie goes to the earlier row           |
| `find(test)`                 | the first row for which the closure returns `Ok(true)`                  |
| `some(test)` / `every(test)` | whether the closure is true for any row / for all rows; both stop early |

A key is an `EventKey`; a plain `i64` time works as one. For other key
kinds, build one with `EventKey::time_range(begin, end)` or
`EventKey::interval(label, begin, end)`, both of which return an error if
`begin` is after `end`. `row.key()` gives a row's key back as an
`EventKey`. Lookups by key are binary searches, so they stay fast on big
series.

```rust
use pond_rs::{Column, EventKey, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let s = TimeSeries::new(
        "cpu",
        vec![0, 1_000, 2_500],
        vec![Column::required("load", vec![0.2, 0.9, 0.4])],
    )?;

    assert_eq!(s.at(-1).unwrap().begin(), 2_500); // the last row
    assert_eq!(s.bisect(1_200), 2); // between rows 1 and 2
    assert!(s.includes_key(1_000));
    assert!(!s.includes_key(1_200));

    assert_eq!(s.at_or_before(1_200).unwrap().begin(), 1_000);
    assert_eq!(s.at_or_after(1_200).unwrap().begin(), 2_500);
    assert!(s.at_or_before(-5).is_none()); // every row is after it

    // 1,750 is 750 ms from both 1,000 and 2,500: the earlier row wins.
    assert_eq!(s.nearest(1_750).unwrap().begin(), 1_000);
    // Outside the series: the last row.
    assert_eq!(s.nearest(99_000).unwrap().begin(), 2_500);

    let first_busy = s.find(|r| Ok(r.number("load")? > Some(0.5)))?;
    assert_eq!(first_busy.unwrap().key(), EventKey::time(1_000));
    assert!(s.every(|r| Ok(r.number("load")?.is_some()))?);

    // A backwards range is refused when the key is built.
    assert!(EventKey::time_range(2_000, 1_000).is_err());
    Ok(())
}
```

## Picking a time span

These keep the rows in a stretch of time. Every test includes both ends.
A span is an `EventKey` (usually `EventKey::time_range(begin, end)?`), so a
span whose start is after its end is refused when it is built.

| Call                 | Keeps                                                                            |
| -------------------- | -------------------------------------------------------------------------------- |
| `within(begin, end)` | rows wholly inside `begin..=end` (an error if `begin > end`)                     |
| `contained_by(span)` | rows wholly inside `span`                                                        |
| `overlapping(span)`  | rows that touch `span` at all, keys unchanged                                    |
| `trim(span)`         | the same rows as `overlapping`, with time ranges and intervals clipped to `span` |
| `before(t)`          | rows that end strictly before `t`                                                |
| `after(t)`           | rows that start strictly after `t`                                               |

For a series keyed by moments, `contained_by`, `overlapping` and `trim`
keep the same rows. They differ when rows are spans:

```rust
use pond_rs::{Column, EventKey, TimeRangeKeys, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    // Three jobs, each running from begin to end.
    let jobs = TimeSeries::from_time_ranges(
        "jobs",
        TimeRangeKeys {
            begin: vec![0, 2, 8],
            end: vec![10, 5, 9],
        },
        vec![Column::required("id", vec!["a", "b", "c"])],
    )?;
    let span = EventKey::time_range(3, 20)?;

    // Wholly inside 3..=20: only c.
    assert_eq!(jobs.contained_by(span.clone()).len(), 1);
    // Touching it at all: all three.
    assert_eq!(jobs.overlapping(span.clone()).len(), 3);

    // Clipped to start at 3. a (now 3..10) and b (now 3..5) start together,
    // so the rows are re-sorted by end: b first.
    let clipped = jobs.trim(span);
    let ids: Vec<_> = clipped.column("id")?.strings()?.iter().collect();
    assert_eq!(ids, [Some("b"), Some("a"), Some("c")]);
    assert_eq!(clipped.key().begin(), &[3, 3, 8]);

    assert_eq!(jobs.before(6).len(), 1); // b ends at 5
    assert_eq!(jobs.after(1).len(), 2); // b and c start after 1
    Ok(())
}
```

`trim` re-sorts only when clipping put two rows that now start together in
the wrong order, as above. pond-ts had a bug here: it left them out of
order, which broke later lookups. It was fixed in pond-ts at the same time.

Four more calls look at the whole series' span, from the first start to the
latest end:

| Call                 | Gives                                                           |
| -------------------- | --------------------------------------------------------------- |
| `time_range()`       | that span as an `EventKey`, or `None` for an empty series       |
| `overlaps(span)`     | whether it touches `span` (`false` for an empty series)         |
| `contains(span)`     | whether it wholly contains `span` (`false` for an empty series) |
| `intersection(span)` | the shared part, or `None` if they do not overlap               |

To compare two series, pass the other's span:
`b.time_range().is_some_and(|r| a.overlaps(r))`.

```rust
use pond_rs::{Column, EventKey, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let a = TimeSeries::new("a", vec![0, 5_000, 10_000], vec![Column::required("v", vec![1.0, 2.0, 3.0])])?;
    let b = TimeSeries::new("b", vec![8_000, 20_000], vec![Column::required("v", vec![4.0, 5.0])])?;

    assert_eq!(a.time_range(), Some(EventKey::time_range(0, 10_000)?));
    assert!(b.time_range().is_some_and(|r| a.overlaps(r)));
    assert!(!a.contains(b.time_range().unwrap()));
    assert_eq!(
        a.intersection(b.time_range().unwrap()),
        Some(EventKey::time_range(8_000, 10_000)?)
    );

    // Rows of a inside the shared part: just the one at 10 s.
    assert_eq!(a.within(8_000, 10_000)?.len(), 1);
    Ok(())
}
```

## Changing columns

- `map_numbers(col, |v| ..)` applies a function to every value of a number
  column. Gaps stay gaps and are not passed in; a `NaN` result becomes a
  gap. `map_strings`, `map_booleans` and `map_decimals` do the same for the
  other kinds.
- `with_column(Column)` adds a column you built yourself; it must be as
  long as the series.
- `select(&cols)` keeps only the named columns (in their existing order),
  `rename(&[(from, to)])` renames them, and `as_time(At::Begin)` turns an
  interval or time-range key into a plain time.

```rust
use pond_rs::{Agg, At, Column, Reducer, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let s = TimeSeries::new(
        "t",
        vec![0, 30_000, 60_000],
        vec![
            Column::optional("celsius", vec![Some(20.0), None, Some(25.0)]),
            Column::required("site", vec!["x", "x", "y"]),
        ],
    )?;

    let f = s.map_numbers("celsius", |c| c * 1.8 + 32.0)?;
    assert_eq!(f.column("celsius")?.numbers()?.get(0), Some(68.0));

    // Add a column computed from another one.
    let celsius = s.column("celsius")?.numbers()?;
    let hot: Vec<Option<bool>> =
        celsius.iter().map(|c| c.map(|c| c > 22.0)).collect();
    let with_hot = s.with_column(Column::optional("hot", hot))?;
    assert_eq!(with_hot.column("hot")?.booleans()?.get(2), Some(true));

    // Per-minute averages, renamed, keyed by each minute's start.
    let per_minute = s
        .aggregate(
            &Sequence::every("1m")?,
            &[Agg::of("celsius", Reducer::Avg)],
        )?
        .rename(&[("celsius", "avg_c")])?
        .as_time(At::Begin)?;
    assert_eq!(per_minute.key_name(), "time");
    assert_eq!(per_minute.key().begin(), &[0, 60_000]);
    assert_eq!(per_minute.select(&["avg_c"])?.columns().len(), 1);
    Ok(())
}
```

## Regular grids: `align` and `materialize`

Sensors rarely report on the second. Both of these give one row per bucket
of a `Sequence`, so the result lines up on a regular grid. They differ in
where each row's values come from:

- **`align`** asks "what was the value at this moment?" With
  `AlignMethod::Hold` (the default) that is the latest reading at or before
  the grid point. With `AlignMethod::Linear`, number columns follow a
  straight line between the readings either side (time-keyed series only).
  The result is keyed by interval, like `aggregate`.
- **`materialize`** asks "which reading fell in this bucket?" It takes one
  row from each bucket (`Pick::Last` by default, or `First`, or `Nearest`
  to the sample point) and leaves gaps where a bucket had none. The result
  is keyed by time.

Neither reduces: unlike `aggregate`, nothing is averaged. Every value
column comes out optional, since a grid point can have no value.

```rust
use pond_rs::{Align, AlignMethod, Column, Materialize, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    // Readings at 0 s, 2.5 s and 4 s.
    let s = TimeSeries::new("temp", vec![0, 2_500, 4_000], vec![
        Column::required("c", vec![10.0, 15.0, 18.0]),
    ])?;
    let every_second = Sequence::every("1s")?;

    // Hold: the latest reading at or before each second.
    let held = s.align(&every_second, Align::default())?;
    assert_eq!(held.key().begin(), &[0, 1_000, 2_000, 3_000, 4_000]);
    let got: Vec<_> = held.column("c")?.numbers()?.iter().collect();
    assert_eq!(got, [Some(10.0), Some(10.0), Some(10.0), Some(15.0), Some(18.0)]);

    // Linear: a straight line between the readings either side.
    let linear = Align { method: AlignMethod::Linear, ..Align::default() };
    let lined = s.align(&every_second, linear)?;
    let got: Vec<_> = lined.column("c")?.numbers()?.iter().collect();
    assert_eq!(got, [Some(10.0), Some(12.0), Some(14.0), Some(16.0), Some(18.0)]);

    // Materialize: the reading that fell in each one-second bucket, if any.
    let picked = s.materialize(&every_second, Materialize::default())?;
    assert_eq!(picked.key_name(), "time");
    let got: Vec<_> = picked.column("c")?.numbers()?.iter().collect();
    assert_eq!(got, [Some(10.0), None, Some(15.0), None, Some(18.0)]);
    Ok(())
}
```

Both take options as a struct whose `Default` is pond-ts's default, so you
set only what you change:

- `sample`: which point of each bucket is used, `At::Begin` (default),
  `At::Center` or `At::End`. For `materialize` this is also the row's time.
- `range`: `Some((begin, end))` in epoch milliseconds to cover a chosen
  span instead of the series' own first-to-last range.

Calendar sequences work too: `Sequence::calendar("day", "Europe/London")`
gives one row per local day. To align many hosts or symbols, partition
first: `series.partition_by(&["host"])?.align(..)?` gives each host its own
grid (see [Partitions](./partitions)).

## Duplicate times: `dedupe`

`dedupe(keep)` collapses rows that share a key (the same time; for time
ranges and intervals, the same start, end and label). `Keep` says which row
survives:

| `Keep`           | Keeps                                                         |
| ---------------- | ------------------------------------------------------------- |
| `Last` (default) | the last of the rows                                          |
| `First`          | the first                                                     |
| `Min("col")`     | the one with the smallest value in a number or decimal column |
| `Max("col")`     | the one with the largest                                      |
| `Drop`           | none of them                                                  |
| `Error`          | nothing: returns an error at the first repeated key           |

For `Min` and `Max`, a gap loses to any value, and on a tie the earlier row
wins.

```rust
use pond_rs::{Column, Keep, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    // The same minute reported twice, with different quality scores.
    let s = TimeSeries::new("feed", vec![0, 60_000, 60_000, 120_000], vec![
        Column::required("price", vec![100.0, 101.0, 101.5, 102.0]),
        Column::required("quality", vec![0.9, 0.4, 0.8, 0.9]),
    ])?;

    let last = s.dedupe(Keep::Last)?;
    assert_eq!(last.column("price")?.numbers()?.values(), &[100.0, 101.5, 102.0]);

    let best = s.dedupe(Keep::Max("quality".into()))?;
    assert_eq!(best.column("price")?.numbers()?.get(1), Some(101.5));

    let none = s.dedupe(Keep::Drop)?;
    assert_eq!(none.len(), 2);

    // Use Error to check an assumption: "this feed never repeats a time".
    assert!(s.dedupe(Keep::Error).is_err());
    Ok(())
}
```

## Putting series side by side: `join`

`join` puts the columns of two series next to each other, matching rows by
key. The key and the series name come from the left series. The left
series' value columns come first, then the right's, and every value column
comes out optional, since a row may be missing on one side.

`JoinType` picks which rows survive:

| `how`             | Keeps                          |
| ----------------- | ------------------------------ |
| `Outer` (default) | every key found on either side |
| `Inner`           | only keys found on both sides  |
| `Left`            | every row of the left series   |
| `Right`           | every row of the right series  |

```rust
use pond_rs::{Column, Join, JoinType, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let cpu = TimeSeries::new(
        "cpu",
        vec![0, 1_000, 2_000],
        vec![Column::required("cpu", vec![0.5, 0.6, 0.7])],
    )?;
    let mem = TimeSeries::new(
        "mem",
        vec![1_000, 2_000, 3_000],
        vec![Column::required("mem", vec![40.0, 41.0, 42.0])],
    )?;

    // Only the times both have.
    let both = cpu.join(&mem, Join { how: JoinType::Inner, ..Join::default() })?;
    assert_eq!(both.key().begin(), &[1_000, 2_000]);
    assert_eq!(both.name(), "cpu"); // the left series' name

    // Every time either has; the missing side is a gap.
    let all = cpu.join(&mem, Join::default())?;
    assert_eq!(all.key().begin(), &[0, 1_000, 2_000, 3_000]);
    let mem_col: Vec<_> = all.column("mem")?.numbers()?.iter().collect();
    assert_eq!(mem_col, [None, Some(40.0), Some(41.0), Some(42.0)]);
    let cpu_col: Vec<_> = all.column("cpu")?.numbers()?.iter().collect();
    assert_eq!(cpu_col, [Some(0.5), Some(0.6), Some(0.7), None]);
    Ok(())
}
```

The rules, all as in pond-ts:

- **Keys must match exactly.** A reading at 1,000 ms does not pair with one
  at 1,001 ms. To join readings that are close but not equal, put both on
  the same grid first with [`align` or `materialize`](#regular-grids-align-and-materialize).
- **Both series need the same kind of key**: time with time, time range
  with time range, interval with interval. The key names may differ.
- **Repeated keys pair one to one, in order.** If time 5 appears twice on
  the left and three times on the right, you get two matched rows and one
  right-only row, not 2 × 3 = 6 rows. Use [`dedupe`](#duplicate-times-dedupe)
  first if you want one row per time.
- **Interval labels.** Interval keys match on begin, end and label. Text
  labels compare the way JavaScript's `localeCompare` does in English (so
  `"a"` sorts before `"B"`, and the two ways of writing `é` in Unicode are the
  same label). Number labels sort before text ones. An outer join that would
  mix number labels from one side with text labels from the other is an
  error.

### Two series with the same column name

If both series have a column called `value`, the join refuses by default
and names the column. `OnConflict::Prefix` renames each repeated column to
`<prefix>_<name>`, one prefix per series; columns that are not repeated
keep their names. You can also [`rename`](#changing-columns) one side
yourself first.

```rust
use pond_rs::{Column, Join, OnConflict, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let a = TimeSeries::new(
        "a",
        vec![0, 1_000],
        vec![
            Column::required("value", vec![1.0, 2.0]),
            Column::required("a_only", vec![9.0, 9.0]),
        ],
    )?;
    let b = TimeSeries::new("b", vec![0, 1_000], vec![Column::required("value", vec![3.0, 4.0])])?;

    let err = a.join(&b, Join::default()).unwrap_err();
    assert!(err.to_string().contains("duplicate column names: value"));

    let joined = a.join(
        &b,
        Join {
            on_conflict: OnConflict::Prefix(vec!["a".into(), "b".into()]),
            ..Join::default()
        },
    )?;
    let names: Vec<_> = joined.columns().iter().map(|c| c.name()).collect();
    assert_eq!(names, ["a_value", "a_only", "b_value"]);
    Ok(())
}
```

### More than two: `join_many`

`TimeSeries::join_many(&[&a, &b, &c], options)` joins left to right, as
repeated `join` calls with the same `how`. Repeated names are found across
all the series first, so `Prefix` takes one prefix per series. A list of
one series comes back unchanged; an empty list is an error.

```rust
use pond_rs::{Column, Join, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let times = vec![0, 1_000];
    let cpu = TimeSeries::new("cpu", times.clone(), vec![Column::required("cpu", vec![0.5, 0.6])])?;
    let mem = TimeSeries::new("mem", times.clone(), vec![Column::required("mem", vec![40.0, 41.0])])?;
    let disk = TimeSeries::new("disk", times, vec![Column::required("disk", vec![7.0, 8.0])])?;

    let wide = TimeSeries::join_many(&[&cpu, &mem, &disk], Join::default())?;
    let names: Vec<_> = wide.columns().iter().map(|c| c.name()).collect();
    assert_eq!(names, ["cpu", "mem", "disk"]);
    assert_eq!(wide.len(), 2);
    Ok(())
}
```

`join` runs on one thread. When every row of a side lands in the output once
and in order (always the left side of a `Left` join, and both sides when the
keys match one for one), that side's columns are shared rather than copied.
To bring across only some columns, [`select`](#changing-columns) them on
the other side first. `join` is not on `PartitionedSeries`.
