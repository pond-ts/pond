# pond-rs (Rust)

**pond-rs** is pond written in Rust. It does the same time series work as
the `pond-ts` core (rolling windows, buckets by calendar day in a time zone,
gaps that stay gaps, per-entity work) and gives **the same answers as pond-ts,
to the last bit**. It is built mainly for AI agents that write Rust, and for
anyone who wants pond's rules at native speed.

:::caution Early work, not on crates.io yet

pond-rs is being built now. It is not published to crates.io; you depend on
it straight from GitHub (see [Getting started](./getting-started)). The API
can still change between commits. These pages describe what exists in the
repository today, and they grow as more of it is built.

:::

```toml
# Cargo.toml
[dependencies]
pond-rs = { git = "https://github.com/pond-ts/pond" }
```

## Why a Rust version

- **Speed and threads.** JavaScript runs one core at a time. pond-rs runs
  independent pieces of work on several cores, and on one core it was
  2.4× to 13× faster than pond-ts in every benchmark so far but one, where
  the two tied. On the first benchmark (1 million rows), pond-rs
  on 4 cores took 141–159 ms where polars took 209–231 ms and pond-ts about
  3 seconds. Details on [Performance](./performance).
- **The same answers.** Every operation pond-ts also has is checked against
  pond-ts's own output on a shared set of test cases, bit for bit. A result does not
  change with the number of threads either.
- **Time is the point.** General table libraries like polars are very good
  at tables. pond's strengths are time-aware ones: rows keyed by a moment,
  a span or a labelled bucket; calendar days that know a day can be 23 or
  25 hours long; and clear rules for missing values.
- **Errors that say what to fix.** Column types are checked when the code
  runs, and each error names the call, the column and what was expected,
  so an agent can fix its code from the message alone.

## What exists today

| Area                  | In pond-rs now                                                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Series and keys       | Rows keyed by a time, a time range, or a labelled interval; `parse_time` reads times written as text                                                                                                                                                    |
| Column kinds          | Numbers, exact decimals, text, true/false, lists; any may have gaps                                                                                                                                                                                     |
| Windows and buckets   | `rolling` over a time window (trailing, leading or centred) or the last N rows, or on a regular grid; `aggregate` into fixed buckets (`"5m"`) or calendar buckets in a time zone                                                                        |
| Reducers              | every pond-ts reducer: `count`, `sum`, `avg`, `min`, `max`, `first`, `last`, `median`, `stdev`, percentiles, `keep`, `difference`, `unique`, `top`, `samples`                                                                                           |
| Row by row            | `diff`, `rate`, `pct_change`, `shift`, `cumulative`, `fill`                                                                                                                                                                                             |
| Along a column        | `by_column` (bins by value: histograms, per-km splits, time in zone), `rolling_by_column` (a window along distance or another rising column); `by_value` (a series keyed by distance or another rising number)                                          |
| Smoothing and bands   | `smooth` (EMA, moving average, loess), `baseline` / `outliers`, `scan` (a running total of your own), `sample`                                                                                                                                          |
| Finding rows          | `at`, `bisect`, `at_or_before` / `at_or_after`, `nearest`, `find`, `some` / `every`                                                                                                                                                                     |
| Time spans            | `within`, `contained_by`, `overlapping`, `trim`, `before` / `after`; `time_range`, `overlaps`, `intersection`                                                                                                                                           |
| Picking and changing  | `slice`, `tail`, `first` / `last`, `filter` (a Rust closure per row), `reduce` (one row for the whole series), `with_column`, `map_numbers` and friends, `select`, `rename`; `as_time`, `as_time_range`, `as_interval`, `offset_time` to change the key |
| Regular grids         | `align` (value at each grid point: hold or straight line), `materialize` (one reading per bucket), `dedupe` (repeated times)                                                                                                                            |
| Joining and reshaping | `join` and `join_many` (columns side by side, matched by key), `concat` (rows stacked), `collapse` (several columns into one), `pivot_by_group` (long rows into wide)                                                                                   |
| Per entity            | `partition_by` / `group_by` on one or more columns, partitions run on several cores                                                                                                                                                                     |
| Arrow and JSON        | Read and write Arrow IPC (Feather v2) files and streams, compressed or not; columns can share the file's memory instead of copying it. Read and write pond-ts's JSON format                                                                             |

**Started:** financial studies. Moving averages and rolling statistics,
the moving-average family (MACD, …), bands (Bollinger, Keltner, …) and the
first momentum studies (RSI, stochastics, …) are built; see
[Finance studies](./finance-studies).

**Not built yet:** the other financial studies (CCI, ADX, OBV, …),
the live (streaming) layer, and a WASM build that
pond-ts can call. They come in roughly that order; see the
[roadmap](#roadmap) below.

## Roadmap

pond-rs follows a written plan in the repository
([`docs/rfcs/pond-rs.md`](https://github.com/pond-ts/pond/blob/main/docs/rfcs/pond-rs.md)
for the reasoning, `PLAN.md` for the current steps). In order:

1. **Batch core** (done). The first slice, R1a, met every target it set
   itself; R1b added the rest of pond-ts's batch operations, step by step.
2. **Financial studies** (in progress), checked against the same pandas / TA-Lib test
   cases pond-ts uses.
3. **Live layer**: series that update as data arrives.
4. **WASM bridge**: the same Rust code running inside pond-ts where it
   measurably helps.

Charts, React and `@pond-ts/process` stay TypeScript only.
