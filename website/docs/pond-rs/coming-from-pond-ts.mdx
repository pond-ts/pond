# Coming from pond-ts

pond-rs gives the same answers as pond-ts; the parity tests compare the two
on the same inputs, bit for bit, including the inputs where pond-ts throws an
error. What changes is the shape of the code, because Rust is not
TypeScript, and a short list of places where pond-rs refuses something
pond-ts lets through.

## Names

Methods are the pond-ts names in Rust's `snake_case`.

## Types are checked when the code runs

pond-ts tracks every column's name and type in TypeScript's type system, so
`series.get('cpu')` is known to be a number before the code runs. Rust
cannot express "this series has a number column called `cpu`" without a lot
of machinery, so pond-rs checks when the code runs instead, as polars does.
`column("cpu")?` fails if there is no such column and lists the ones there
are; `.numbers()?` fails if it holds text. The errors are written to be
fixed from the message alone.

## Where pond-rs is stricter

Each of these is a case where pond-ts quietly does something surprising and
pond-rs returns an error instead.

- **A study on a missing or text column.** Most of pond-ts's financial
  studies give a column of all gaps, so a typo in the column name looks like "no
  data" (logged as a pond-ts issue, [PND-STUDYSRC]). pond-rs returns an
  error naming the column.
- **Number reducers on text.** pond-ts runs them anyway: `sum` of a text
  column gives 0 and `avg` gives gaps. pond-rs allows only `count`, `first`
  and `last` on text and true/false columns.
- **`fill` mistakes.** An unknown column, `Linear` on a column that is not
  numbers, or a fill value of the wrong kind is an error.
- **Half milliseconds.** pond-rs keeps every time in whole milliseconds.
  `as_time(At::Center)` on an interval an odd number of milliseconds long
  would land on a half millisecond, where pond-ts gives e.g. `2499.5`;
  pond-rs returns an error rather than a different answer.
- **Huge numbers in `rolling`.** A rolling `sum` or `avg` over values of
  2^960 (about 10^289) or more, or a `stdev` over values of 2^480 (about
  10^144) or more, is an error. pond-ts switches to a slower exact method
  for these; pond-rs has not built it yet.
- **`materialize` on a half millisecond.** With `At::Center` on buckets an
  odd number of milliseconds long, the row's time would be on a half
  millisecond; pond-rs returns an error (pond-ts gives e.g. `1.5`).
- **`dedupe` with `Keep::Min` / `Max`** must name a number or decimal
  column, checked before anything runs. pond-ts looks at the column only
  when it meets a duplicate, and quietly keeps the first row if the column
  does not exist.
- **`join_many` of no series** is an error that says so (pond-ts fails
  reading `undefined`).
- **Very large years and odd offsets in `parse_time`.** Years beyond
  ±9999, and offsets with a fraction of a second (`+00:00:00.5`), are
  errors. pond-ts reads both; for the offset, the library pond-rs uses
  would round to the second, so pond-rs refuses rather than be half a
  second out.
- **Lookup keys and spans are checked when built.** `EventKey::time_range`
  and `EventKey::interval` refuse a start after the end straight away, even
  where pond-ts never reads the key (such as `nearest`, `overlapping` or
  `trim` on an empty series). A number label must be finite, and times are whole
  milliseconds.
- **`offset_time` past the time limit.** Moving a key beyond
  `MAX_TIME_MS` is an error; pond-ts allows it, but such a key cannot be
  read back. Offsets are whole milliseconds (pond-ts takes `0.5`).
- **JSON input** refuses times that are not whole milliseconds or are
  past `MAX_TIME_MS`, a missing `name`, and text with a lone surrogate.
  Columns JSON also refuses cells pond-ts quietly converts and numbers too
  big to store; see [Arrow and JSON](./arrow#json).
- **List columns.** Each of these is an error in pond-rs where pond-ts
  quietly gives an odd result:
  - An `array_*` call on a column that is not a list. pond-ts gives an
    empty series, or for `arrayAggregate` overwrites the column with gaps.
  - `partition_by` on a list column. pond-ts groups lists by their text, so
    `["a,b"]` and `["a", "b"]` land together.
  - A number reducer in `array_aggregate` given a kind other than number.
  - A number that is not finite from `map_arrays` or in a fill value
    (pond-ts leaves a gap).

  Also, `First`, `Last`, `Keep` and `array_explode` with no kind take the
  kind of the elements; pond-ts assumes text and so fails on numbers. `shift` works
  on list columns (pond-ts throws).

- **`smooth` and `baseline` on the wrong column.** An unknown column or
  one that is not numbers is an error. pond-ts passes the series through
  unchanged (`smooth` on an unknown column) or gives a gap in every row,
  on a partitioned series too.
- **`baseline_named`** refuses a name that is the key's, or the same name
  twice; pond-ts only checks the existing columns.
- **An option a smoothing method does not take** (`warmup` on a loess,
  say) is an error when the code runs; pond-ts's types refuse it when
  the code is checked.
- **`concat` of series whose interval labels differ in kind** (text in
  one, numbers in another) is an error; pond-ts allows the mix.
- **`sum` on a list column in `by_column` / `rolling_by_column`** is an
  error, as in every other call; pond-ts gives 0 ([PND-KINDREDUCE]).
- **A repeated rename.** `rename` with the same `from` twice is an error
  (pond-ts's object syntax cannot express it).

## Where pond-rs does more

- **Repeatable random samples.** `Sample::Reservoir` takes a seed, so
  the same seed picks the same rows; pond-ts's reservoir has none. The
  picked rows keep their order in the series, where pond-ts sorts them by
  key, which can order rows sharing a key differently. On a partitioned
  series each partition gets its own seed, made from yours, so those picks
  repeat too.
- **Exact decimals.** A column kind of their own, for money and other exact
  values; see [Series and columns](./series-and-columns#value-columns-five-kinds).
- **`with_column`** takes any kind of column and you choose required or
  optional. pond-ts's `withColumn` takes numbers only and always makes the
  column optional.
- **`shift`** works on every column kind (pond-ts: numbers only).
- **`group_by`** takes several columns (pond-ts: one), and partition keys
  are typed values (`Value::String("a")`) rather than strings to parse.

## Where pond-rs fixes a pond-ts bug

Building pond-rs turned up several pond-ts bugs. Where pond-rs could not
copy the bug without being wrong, it does the right thing, and the pond-ts
bug is logged in `PLAN.md` to fix there.

- `Keep` on a list column keeps a list that is the same in every row.
  pond-ts compares the lists as objects, so two equal lists in different
  rows count as different and give a gap ([PND-ARRAYKEY]). pond-rs compares
  the elements exactly, so `[0]` and `[-0]` count as different.
- After `map_numbers` turns values into gaps, a required column becomes
  optional. pond-ts keeps it marked required, which its own `fromJSON` then
  refuses ([PND-MAPREQ]).
- A column read from Arrow with nulls in it is optional. pond-ts's
  `fromArrow` marks every column required, even one with nulls, so its own
  save-and-reload then fails ([PND-ARROWREQ]). pond-rs takes the flag from
  the Arrow field's nullability.

## Small differences

- **`collapse`'s output is optional when it has gaps.** pond-ts marks it
  required even then, so its own `fromJSON` refuses the result (logged
  as a pond-ts issue, [PND-COLLAPSEREQ]). Decimal groups in
  `pivot_by_group`, which pond-ts has no kind for, are named in full
  (`1.50_cpu`).
- **`reduce` returns a `Reduced`**, read by output name with `number`,
  `string` and so on, rather than a plain object. The one-column form
  (`reduce('cpu', 'avg')`) is `reduce_number` / `reduce_value`; custom
  reducer functions are not built.
- **`dedupe` has no custom keep function** yet (pond-ts takes a closure that
  builds the surviving row), and `align` / `materialize` take a range as an
  epoch-millisecond pair rather than a pond-ts `BoundedSequence`.
- **Text labels in `join`** compare as Node's `localeCompare` does under
  an English (or the root) locale. Node uses the machine's locale, so
  pond-ts on a machine set to another language can order interval labels
  differently; pond-rs always uses the root order.
- **A partitioned `scan` gives each partition its own copy of the start
  value.** pond-ts hands every partition the same start object, so a step
  that changes it in place carries state from one partition into the
  next. In pond-rs every partition starts from a fresh copy.
- **`align` with `Linear` holds exact decimal columns** instead of drawing a
  line through them, since a point between two decimals is generally not
  exact. pond-ts has no decimal kind.

- **A plain number as a span.** `contained_by(5_000)` or `overlaps(5_000)`
  treats the number as a moment. pond-ts throws on a bare number there;
  passing it a `Time` gives the same answer as pond-rs.
- **`NaN` and infinities when building a series.** pond-ts's
  `fromJSON` and `new TimeSeries` refuse them; pond-rs reads them as gaps
  in a number column (and refuses them in a required one).

- The key column cannot be renamed yet. An interval key is always named
  `interval` and a time key `time`; if you need `day_start` in a file,
  rename that one Arrow field.
- When pond-ts builds a text column it decides by itself whether to store
  it as a dictionary (a list of distinct strings plus a number per row).
  pond-rs keeps whatever it was given: built from Rust values, plain text;
  read from Arrow, as it was in the file. The values are the same either
  way.
- Time-zone rules: pond-rs carries its own copy of the time-zone database;
  pond-ts uses the one in its JavaScript engine. They agree unless the two
  copies are from releases that disagree about a zone's history. This
  affects calendar buckets and `parse_time_in` alike; checks found it in
  Casablanca's predicted future clock changes and in `EST5EDT` before 1967.
- pond-ts's typed `groups` option on `partitionBy` (declare the partition
  values up front) is not built; nothing has needed it in Rust.
