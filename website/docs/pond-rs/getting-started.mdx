# Getting started with pond-rs

This page builds one small program: hourly temperature readings, turned into
one row per calendar day in New York. It shows the three things nearly every
pond-rs program does: build a series, run an operation, read the values
back.

## Add the dependency

<Tabs groupId="language" queryString>
<TabItem value="rust" label="Rust" default>

pond-rs is on [crates.io](https://crates.io/crates/pond-rs):

```toml
# Cargo.toml
[dependencies]
pond-rs = "0.1"
```

or run `cargo add pond-rs`. pond-rs needs Rust 1.88 or newer. Every type
and function is described in the API reference on
[docs.rs](https://docs.rs/pond-rs). To try work not yet released, depend on
the repository instead:
`pond-rs = { git = "https://github.com/pond-ts/pond" }`.

The crate is named `pond-rs`; in code it is `pond_rs`.

</TabItem>
<TabItem value="js" label="JavaScript">

The same Rust code, compiled to WebAssembly, is on npm as
[`@pond-ts/rs`](https://www.npmjs.com/package/@pond-ts/rs), with pond-ts's
method names and argument shapes:

```sh
npm install @pond-ts/rs
```

It runs in Node 20 or newer and in browsers (through a bundler or plain
ES modules). See [From JavaScript](./javascript) for browser set-up and how
it differs from pond-ts.

</TabItem>
</Tabs>

## Build a series, bucket it by day

<Tabs groupId="language" queryString>
<TabItem value="rust" label="Rust" default>

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries, parse_time_in};

fn main() -> Result<(), pond_rs::PondError> {
    // One reading an hour for 72 hours, starting at midnight in New York on
    // Saturday 7 March 2026. Times are epoch milliseconds; `parse_time_in`
    // turns a date written as text into one.
    let start = parse_time_in("2026-03-07", "America/New_York")?;
    assert_eq!(start, 1_772_859_600_000); // 05:00 UTC
    let hour = 3_600_000_i64;
    let times: Vec<i64> = (0..72).map(|h| start + h * hour).collect();

    // The sensor missed one reading (hour 30). `None` marks the gap.
    let temps: Vec<Option<f64>> = (0..72)
        .map(|h| {
            if h == 30 {
                None
            } else {
                Some(10.0 + (h % 24) as f64 * 0.5)
            }
        })
        .collect();

    let series = TimeSeries::new(
        "weather",
        times,
        vec![Column::optional("temp", temps)],
    )?;

    // One row per calendar day in New York.
    let days = series.aggregate(
        &Sequence::calendar("day", "America/New_York")?,
        &[
            Agg::new("readings", "temp", Reducer::Count),
            Agg::new("high", "temp", Reducer::Max),
        ],
    )?;

    // Sunday 8 March is the day the clocks go forward: it is 23 hours long.
    let begin = days.key().begin();
    let end = days.key().end().unwrap();
    let lengths: Vec<i64> = (0..days.len())
        .map(|i| (end[i] - begin[i]) / hour)
        .collect();
    assert_eq!(lengths, [24, 23, 24, 24]);

    // 72 hourly readings cover four New York days, not three, because one
    // day was short. The gap is not counted.
    let readings: Vec<Option<f64>> =
        days.column("readings")?.numbers()?.iter().collect();
    assert_eq!(readings, [Some(24.0), Some(22.0), Some(24.0), Some(1.0)]);

    println!("{} days", days.len());
    Ok(())
}
```

</TabItem>
<TabItem value="js" label="JavaScript">

```js
import assert from 'node:assert/strict';
import { Sequence, Time, TimeSeries } from '@pond-ts/rs';

// One reading an hour for 72 hours, starting at midnight in New York on
// Saturday 7 March 2026. Times are epoch milliseconds.
const start = Time.parse('2026-03-07', { timeZone: 'America/New_York' });
assert.equal(start.timestamp, 1_772_859_600_000); // 05:00 UTC
const hour = 3_600_000;

// The sensor missed one reading (hour 30). `undefined` marks the gap.
const rows = [];
for (let h = 0; h < 72; h++) {
  rows.push([
    start.timestamp + h * hour,
    h === 30 ? undefined : 10 + (h % 24) * 0.5,
  ]);
}

const series = new TimeSeries({
  name: 'weather',
  schema: [
    { name: 'time', kind: 'time' },
    { name: 'temp', kind: 'number', required: false },
  ],
  rows,
});

// One row per calendar day in New York.
const days = series.aggregate(
  Sequence.calendar('day', { timeZone: 'America/New_York' }),
  {
    readings: { from: 'temp', using: 'count' },
    high: { from: 'temp', using: 'max' },
  },
);

// Sunday 8 March is the day the clocks go forward: it is 23 hours long.
const { rows: out } = days.toJSON({ rowFormat: 'object' });
assert.deepEqual(
  out.map((r) => (r.interval.end - r.interval.start) / hour),
  [24, 23, 24, 24],
);

// 72 hourly readings cover four New York days, not three, because one
// day was short. The gap is not counted. `numbers` reads a whole column
// as a Float64Array (NaN for a gap).
assert.deepEqual([...days.numbers('readings')], [24, 22, 24, 1]);

console.log(`${days.length} days`);

// A series lives in WebAssembly memory: free it when done.
days.free();
series.free();
```

The calls are pond-ts's: a `TimeSeries` from a schema and rows, and
`aggregate` with a `Sequence` and a mapping of output columns. The steps
below name the Rust calls; each has the pond-ts counterpart you would
expect.

</TabItem>
</Tabs>

What happened, step by step:

1. **`TimeSeries::new`** takes a name, the times (epoch milliseconds, in
   order; repeats are allowed) and the value columns. `parse_time_in`
   turned the date text into milliseconds; see
   [Times written as text](./series-and-columns#times-written-as-text). Every column must be
   as long as the times.
2. **`Column::optional`** makes a column that may have gaps. A `None` is a
   gap. `Column::required` makes one that may not, and building the series
   fails if it has one.
3. **`Sequence::calendar("day", "America/New_York")`** describes calendar
   days in that time zone, including the short and long days when the
   clocks change. `Sequence::every("1h")` would give fixed-length buckets
   instead.
4. **`aggregate`** puts each row in the bucket it falls in and reduces each
   bucket to one row. Each `Agg` says: write this reducer of that source
   column to this output column.
5. **Reading back.** `days.column("readings")?` finds the column,
   `.numbers()?` says you expect numbers, and `.get(i)` or `.iter()` give
   `Option<f64>`, with `None` for a gap.

The result is keyed by interval: each row has a start, an end, and a label
(here, the start). [Series and columns](./series-and-columns) explains the
three kinds of key.

## When something is wrong

Every call returns `Result<_, PondError>`. The error says which call failed,
which column, and what to do about it. These are real messages:

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries};

fn main() {
    let series = TimeSeries::new(
        "weather",
        vec![0, 1_000],
        vec![Column::required("temp", vec![20.5, 21.0])],
    )
    .unwrap();

    // A typo in a column name lists the columns there are.
    let err = series
        .aggregate(
            &Sequence::every("1h").unwrap(),
            &[Agg::of("tmp", Reducer::Avg)],
        )
        .unwrap_err();
    assert_eq!(
        err.to_string(),
        "aggregate: no column named 'tmp' (columns: temp)"
    );

    // A gap in a required column says how to allow gaps.
    let err = TimeSeries::new(
        "weather",
        vec![0, 1_000],
        vec![Column::required("temp", vec![Some(20.5), None])],
    )
    .unwrap_err();
    assert_eq!(
        err.to_string(),
        "TimeSeries::new: required column 'temp' has a gap at row 1; use Column::optional if gaps are allowed"
    );

    // A bad duration says what a good one looks like.
    let err = Sequence::every("5 minutes").unwrap_err();
    println!("{err}");
}
```

`PondError` is an ordinary enum, so code can also `match` on its variants
(`UnknownColumn`, `WrongKind`, `InvalidData`, …) instead of reading the
text.
