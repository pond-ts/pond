# @pond-ts/fit

A **fitness / activity domain library** on pond-ts. The name reads _fitness_
(with the happy bonus that it parses `.fit` files); it is **not** a FIT-_format_
parser — file parsing is just one input. Its job is "Strava as an API": free,
ergonomic tools to work with **your own** activity data — parse it, analyze it,
slice it, convert units — with a fluent object model over pond's generic
`TimeSeries`.

**Install** — `npm install pond-ts @pond-ts/fit`. Peer-depends on `pond-ts`.

```ts
import { km, minutes } from '@pond-ts/fit';
import { readActivity } from '@pond-ts/fit/files';

const ride = readActivity(bytes); // FIT, GPX or TCX

ride.sport; // "ride"
const stats = ride.stats();
stats.distance?.miles; // Distance — .miles / .km / .meters
stats.time.moving?.format(); // "7:00:54"
stats.power.normalized?.watts; // null with no power meter

const splits = ride.splits(km(1)); // Sections
splits.at(3)?.stats().pace.average?.format('imperial'); // "10:31/mi"

const window = ride.section({
  elapsed: { from: minutes(20), to: minutes(40) },
});
window.stats().elevation.gain?.feet;

const analysis = ride.analyze({ athlete: profile });
analysis.power.intensityFactor; // null without FTP
analysis.load?.value; // cycling TSS
ride.power.bestEffort(minutes(20))?.power.watts;
```

## The stack (three layers)

```
pond-ts            generic TimeSeries + operators (rolling, byColumn, fill, validity)
  └─ @pond-ts/fit  the FITNESS domain:
        • quantity types     Distance, Duration, Speed/Pace, Power, HeartRate, Cadence, Elevation
        • canonical series   the activity TimeSeries schema (one SI-normalized column vocabulary)
        • operators (pure)   geo (track/splits/profiles/best-efforts), power (NP/curve/zones), zones
        • Activity / Section the object model over the operators + quantities
```

**The object model sits on a functional core.** `section.stats()` delegates to
the pure `sectionStats(prepared, span)`. Logic lives in composable, tested
functions; `Activity`/`Section` add ergonomics + memoization. Drop to the
functional layer (`activity.prepared()`, `activity.toSeries()`) or stay with the
objects — both first-class.

## Design tenets

- **The athlete goes on an analysis.** Anything needing FTP / body weight /
  zone definitions comes from `section.analyze({ athlete })`, which resolves
  the athlete's dated settings to the activity's date. `Activity` wraps only
  the activity's own evidence; a missing setting makes only the results that
  need it `null`.
- **Gap-honest.** Sustained coasts/dropouts break the line (NaN), never
  interpolate across a hole; missing channels are absent, not zero.
- **Ingest membrane.** Messy formats in (Strava exports, `.fit`/`.gpx`/`.tcx`,
  dropped samples, `-1`/`255` sentinels, unit quirks), **one clean canonical
  activity** out — wrangled once, here, at ingest.
