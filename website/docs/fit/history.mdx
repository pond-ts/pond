# Training history

Some questions span many activities: how much did I run each week this
spring, what's my best 20 minutes this season. `TrainingHistory` answers them.

## Digests

Loading every recording to draw a year of weekly totals would be slow, so a
history works on **digests**: a small JSON summary of each activity that an
app can store beside it.

```ts
import { readFileSync } from 'node:fs';
import { readActivity } from '@pond-ts/fit/files';

const ride = readActivity(readFileSync('hill-ride.fit'));
const run = readActivity(readFileSync('interval-run.fit'));
const d = run.digest();
console.log(d.version, d.sport, d.localStart);
console.log(d.time, d.distance, d.ascent);
console.log(d.pace.map((p) => p.metres));
console.log(JSON.stringify(d).length, 'bytes');
```

```text output
1 run null
{ elapsed: 3083, moving: 2947 } 9702.2 18
[ 400, 804.672, 1000, 1609.344, 3218.688, 5000 ]
955 bytes
```

A digest holds the clocks, distance and ascent; heart rate as seconds at each
beat per minute; the power curve from 1 s to 5 h; and the fastest time over
distances from 400 m to 100 km. Each curve point and pace best says where it
was, in elapsed seconds.

It holds **no athlete settings**. FTP, weight and zones are applied when the
history is read, with the values in force on each activity's date, so a new
FTP never means reading the files again. The heart-rate histogram is there so
time in any heart-rate zones can be worked out later.

`version` says which digest format made it; a history refuses a version it
doesn't know rather than misreading it.

## A history

`TrainingHistory.of` takes digests, full activities, or a mix, and orders
them by start. A full activity is digested, and kept so a result can hand it
back.

```ts
import { TrainingHistory } from '@pond-ts/fit';

const history = TrainingHistory.of([ride, d]);
console.log(history.length, history.covers);
console.log(history.activity(ride.id) === ride, history.activity(run.id));
```

```text output
2 { from: '2026-06-14', to: '2026-06-16' }
true null
```

Days are the local date where each activity happened, from the file's own
local time, so an evening run in Madrid counts on the day it was run, not the
UTC one. A file with no local time (like these examples, so `localStart` is
`null` above) counts on its UTC date.

`between` and `sports` narrow a history:

```ts
const june = history.between({ from: '2026-06-01', to: '2026-06-30' });
const runs = history.sports(['run', 'walk', 'hike']);
console.log(
  june.length,
  runs.digests.map((x) => x.id),
);
```

```text output
2 [ 'fit:2026-06-16T18:00:00.000Z' ]
```

## Rest days and gaps

`covers` is the stretch of days the history is known to be complete for. A day
inside it with no activity is a **rest day**. A day outside it is a **gap**:
nothing is known, so a zero there doesn't mean rest. By default it runs from
the first activity's day to the last one's; pass it when you know more:

```ts
const known = TrainingHistory.of([ride, d], {
  covers: { from: '2026-06-01', to: '2026-06-30' },
});
console.log(known.covers);
```

```text output
{ from: '2026-06-01', to: '2026-06-30' }
```

## Weekly volume

`volume.weekly()` totals each week: count, distance, moving and elapsed time,
ascent, the longest activity, and the same totals by sport. Every week in the
range is there, empty ones too, so the array feeds a chart as it is.

```ts
for (const w of known.volume.weekly())
  console.log(
    w.from,
    w.coverage,
    w.count,
    w.distance.format('km', 1),
    w.elapsed.format(),
    Object.keys(w.bySport).join(','),
  );
```

```text output
2026-06-01 full 0 0.0 km 0:00
2026-06-08 full 1 45.0 km 1:39:54 ride
2026-06-15 full 1 9.7 km 51:23 run
2026-06-22 full 0 0.0 km 0:00
2026-06-29 partial 0 0.0 km 0:00
```

Weeks start on Monday; pass `{ weekStart: 'sunday' }` for Sunday. `coverage`
is `'full'` when every day of the week is covered, `'partial'` when some are,
and `'gap'` when none are. An activity without a moving time adds to elapsed
time but not to moving time.

## Records and the season curve

Records need settings only for watts per kilogram, so `analyze()` takes the
athlete as optional. Each activity uses the settings in force on its own date.

```ts
import { km, minutes } from '@pond-ts/fit';

const season = known.analyze({
  athlete: { weightKg: [{ at: '2026-01-01', value: 72 }] },
});
for (const r of season.power.records({
  durations: [minutes(1), minutes(5), minutes(20)],
}))
  console.log(
    r.duration.format(),
    r.power.format(),
    r.wattsPerKg?.toFixed(2),
    r.day,
    r.section?.label,
  );
```

```text output
1:00 323 W 4.49 2026-06-14 Best 1 min
5:00 310 W 4.30 2026-06-14 Best 5 min
20:00 269 W 3.73 2026-06-14 Best 20 min
```

Every record names its activity, the day and the stretch (`from` and `to`,
elapsed from the activity's start). When the history was given the full
activity, `section` is that stretch as a `Section`, so you can look inside it;
from a digest alone it's `null`. On a tie the earlier activity keeps the
record.

`power.curve()` is the records at every duration a digest keeps (1 s to 5 h),
which is the season's power curve. For a season, narrow the history first:
`history.between({ from, to }).analyze()`.

Pace records are the fastest elapsed time, stops included, over distances a
digest keeps (400 m to 100 km). Records don't pick a sport for you, so narrow
to the sports you mean first, or a ride would hold the running records:

```ts
const onFoot = known.sports(['run']).analyze();
for (const r of onFoot.pace.records({ distances: [km(1), km(5)] }))
  console.log(
    r.distance.format('km'),
    r.time.format(),
    r.pace.format(),
    r.activity,
  );
```

```text output
1.00 km 4:10 4:10/km fit:2026-06-16T18:00:00.000Z
5.00 km 24:49 4:58/km fit:2026-06-16T18:00:00.000Z
```

Asking for a duration or distance a digest doesn't keep is an error, since
the history can't answer it from digests.
