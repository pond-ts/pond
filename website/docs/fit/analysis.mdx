# Analysis and the athlete

Some answers depend on who did the activity: intensity needs their FTP,
zones need their heart rate or pace bands. Those answers come from
`analyze({ athlete })`, never from the activity alone, so the same recording
can be read for anyone.

## The athlete's settings

Settings are dated, because they change: an FTP test in March, another in
June. Each setting is a list of values with the date each took effect, and an
activity uses the one in force on its own date.

```ts norun
interface AthleteProfileJson {
  ftpWatts?: { at: string; value: number }[];
  weightKg?: { at: string; value: number }[];
  hrZone?: (
    | { at: string; maxHr: number }
    | { at: string; bounds: [number, number, number, number] }
  )[];
  paceThreshold?: { at: string; fiveKSeconds: number }[];
}
```

- `ftpWatts`: functional threshold power. Power zones are worked out from it
  (seven bands, from 55 % to 150 % of FTP).
- `weightKg`: body weight, for watts per kilogram.
- `hrZone`: heart-rate zones from a maximum heart rate (five bands at 65, 81,
  89 and 97 % of it) or from four boundaries you set.
- `paceThreshold`: a recent 5 km time, which sets six pace zones for running,
  walking and hiking.

```ts
import { readFileSync } from 'node:fs';
import { readActivity } from '@pond-ts/fit/files';

const athlete = {
  ftpWatts: [
    { at: '2026-01-01', value: 240 },
    { at: '2026-05-01', value: 250 },
    { at: '2026-09-01', value: 262 },
  ],
  weightKg: [{ at: '2026-01-01', value: 72 }],
  hrZone: [{ at: '2026-01-01', maxHr: 186 }],
  paceThreshold: [{ at: '2026-01-01', fiveKSeconds: 1260 }],
};

const ride = readActivity(readFileSync('hill-ride.fit'));
const analysis = ride.analyze({ athlete });
console.log(analysis.athlete.ftpWatts, analysis.athlete.weightKg);
```

```text output
250 72
```

The ride was on 14 June 2026, so it is read with the 250 W FTP set in May.
`analysis.athlete` says which settings were used.

## What an analysis holds

```ts
const { power, load, zones } = analysis;
console.log('average   ', power.average?.format());
console.log('normalized', power.normalized?.format());
console.log('IF        ', power.intensityFactor?.toFixed(3));
console.log('VI        ', power.variabilityIndex?.toFixed(3));
console.log('load      ', load?.model, load?.value.toFixed(1));
console.log(
  'zones     ',
  zones.power?.length,
  zones.heartRate?.length,
  zones.pace,
);
```

```text output
average    190 W
normalized 228 W
IF         0.913
VI         1.200
load       cycling-tss 138.7
zones      7 5 null
```

- `power.intensityFactor`: normalized power over FTP.
- `power.variabilityIndex`: normalized power over average power; how uneven
  the effort was. It needs no settings.
- `load`: training stress, with the model that made it (`'cycling-tss'`).
  [Normalized power and training stress](./guides/normalized-power) builds it.
- `zones`: time in each power, heart-rate and pace zone. See
  [Time in zones](./guides/time-in-zones).

Pace zones are for running, walking and hiking, so on a ride `zones.pace` is
`null` even with a 5 km time set.

## A missing setting blocks only what needs it

With no FTP, the results that need FTP are `null`, and nothing else is:

```ts
const noFtp = ride.analyze({
  athlete: { hrZone: [{ at: '2026-01-01', maxHr: 186 }] },
});
console.log(
  noFtp.power.normalized?.format(),
  noFtp.power.variabilityIndex?.toFixed(3),
);
console.log(noFtp.power.intensityFactor, noFtp.load, noFtp.zones.power);
console.log(noFtp.zones.heartRate?.map((z) => z.label).join(', '));
```

```text output
228 W 1.200
null null null
Recovery, Endurance, Tempo, Threshold, Anaerobic
```

## Any stretch

`analyze` works on any section, the same way:

```ts
const run = readActivity(readFileSync('interval-run.fit'));
const repeat = run.laps.at(1)!;
const zonesInRepeat = repeat.analyze({ athlete }).zones.heartRate!;
for (const z of zonesInRepeat)
  if (z.seconds > 0) console.log(z.label, z.seconds, 's');
```

```text output
Endurance 19 s
Tempo 143 s
Threshold 21 s
```

## Efficiency and decoupling

`analysis.aerobic` reads output per heartbeat. On a ride with power it is
normalized power over average heart rate (watts per bpm); otherwise it is
speed over heart rate, in metres per heartbeat. Both are on moving time, so a
stop doesn't pull the number around. Higher always means more output for the
same heart rate. It needs no settings.

`decoupling()` compares the first half of a section with the second, split by
moving time so a stop doesn't move the split. A positive `change` means the
second half took more heartbeats for the same output. It also says whether the
stretch suits the question: an interval session or a short stretch comes back
with `cautions`, so it can't pass as a steady endurance reading.

```ts
const aerobic = ride.analyze({ athlete }).aerobic;
console.log(aerobic.efficiency()?.output, aerobic.efficiencyFactor?.toFixed(3));
const d = aerobic.decoupling()!;
console.log(
  d.firstHalf.value.toFixed(3),
  d.secondHalf.value.toFixed(3),
  `${(d.change * 100).toFixed(1)} %`,
);
console.log(d.suitable, d.cautions);
```

```text output
power 1.716
1.679 1.738 -3.5 %
false [ 'variable' ]
```

The hill ride's power isn't steady (its variability index is 1.2), so the
reading is marked `variable`. Read its −3.5 % as "no drift showed", not as an
endurance verdict.

Pass a section to leave out the warm-up, or ask for speed on a ride:

```ts
import { minutes } from '@pond-ts/fit';

const steady = ride.section({
  elapsed: { from: minutes(10), to: minutes(50) },
});
const s = steady.analyze({ athlete }).aerobic.decoupling({ output: 'speed' });
console.log(s?.output, s?.cautions);
```

```text output
speed [ 'variable' ]
```

## Distributions and coasting

`distribution(channel)` says how long the section spent at each level of
power, heart rate, cadence, speed or pace. Bins are in the channel's own unit
(W, bpm, rpm, m/s, s/km), with every bin in between kept, so the array feeds a
bar chart as it is. Power and cadence start at 0, so freewheeling shows.

```ts
const dist = ride.analyze({ athlete }).distribution('power', { binWidth: 50 })!;
for (const b of dist.bins)
  if (b.seconds > 0)
    console.log(`${b.start}-${b.end} W`, Math.round(b.seconds), 's');
```

```text output
0-50 W 682 s
50-100 W 36 s
100-150 W 616 s
150-200 W 1557 s
200-250 W 1164 s
250-300 W 1048 s
300-350 W 483 s
350-400 W 34 s
```

Pace leaves out the time stopped, since a stop has no pace. Pass
`{ time: 'moving' }` to leave stops out of any channel.

`coasting` is a ride's moving time with the pedals still: zero cadence, or
zero power when no cadence was recorded.

```ts
const c = ride.analyze({ athlete }).coasting!;
console.log(c.source, c.duration.format(), `${(c.share * 100).toFixed(1)} %`);
```

```text output
cadence 10:48 11.6 %
```

## Without history

When you just have the numbers, `Profile.of` makes settings with no dates:

```ts
import { Profile } from '@pond-ts/fit';

const simple = ride.analyze({
  athlete: Profile.of({ ftpWatts: 250, weightKg: 72 }),
});
console.log(
  simple.power.intensityFactor?.toFixed(3),
  simple.load?.value.toFixed(1),
);
```

```text output
0.913 138.7
```

`Profile.of` carries FTP and weight only; heart-rate and pace zones need their
basis, so use the dated form for those.
