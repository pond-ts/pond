# Region · Baseline · Marker

The three annotation primitives, with their full prop surface. All render as
`<Layers>` children and share the interaction props (`id`, `selected`,
`selectable`, `hovered`, `editing`, `onChange`) — those are documented once
under [Editing & creating](./editing-and-creating.mdx); this page focuses on
each primitive's **geometry and labelling** props. For the shared model
(registers, depth, the indicator law) see
[The annotation model](./the-annotation-model.mdx).

`Baseline` and `Marker` are near-duals — a horizontal line at a y, a vertical
line at an x — and share most of their surface; `Region` is the shaded span.

## `Region`

A shaded span over an x range — a lap, a zone, a selected interval. Its label
flies as a flag off the left edge.

<ChartExample name="charts-annotation-region" height={240}>
  <ChartsAnnotationRegion />
</ChartExample>

| Prop       | Type                                           | Default | Purpose                                                                                      |
| ---------- | ---------------------------------------------- | ------- | -------------------------------------------------------------------------------------------- |
| `from`     | `number`                                       | —       | Start x in axis units (time or value).                                                       |
| `to`       | `number`                                       | —       | End x in axis units.                                                                         |
| `label`    | `string \| false`                              | auto    | Chip label. Omit ⇒ auto-label `from–to` with the shared x formatter; `false`/`''` ⇒ no chip. |
| `edges`    | `boolean`                                      | `true`  | Draw the vertical side outlines at `from`/`to`. `false` ⇒ fill only (a soft highlight band). |
| `onChange` | `(next: { from: number; to: number }) => void` | —       | Editable: drag the body to move (both edges shift), drag an edge to resize.                  |

Plus the shared interaction props (`id`, `selected`, `selectable`, `hovered`,
`editing`).

## `Baseline`

A horizontal line at a y value, scaled against one row axis. Its label anchors
at the line's height.

<ChartExample name="charts-annotation-baseline" height={240}>
  <ChartsAnnotationBaseline />
</ChartExample>

| Prop            | Type                      | Default     | Purpose                                                                               |
| --------------- | ------------------------- | ----------- | ------------------------------------------------------------------------------------- |
| `value`         | `number`                  | —           | y value in the linked axis's units.                                                   |
| `axis`          | `string`                  | row default | Which `<YAxis>` (by id) to measure against.                                           |
| `label`         | `string \| false`         | auto        | Chip label. Omit ⇒ format `value` with that axis's formatter; `false`/`''` ⇒ no chip. |
| `labelSide`     | `'left' \| 'right'`       | `'left'`    | Which side the near-line label chip sits.                                             |
| `labelPosition` | `'center' \| 'above'`     | `'center'`  | `center` rides on the line; `above` sits just on top of it.                           |
| `indicator`     | `boolean`                 | `false`     | Also pin `value` to its **y-axis** as an on-axis pill.                                |
| `lineWidth`     | `number`                  | `1`         | Stroke width in px. Wins over the theme role's / register's `lineWidth`.              |
| `onChange`      | `(value: number) => void` | —           | Editable: drag vertically to report a new `value`.                                    |

Plus the shared interaction props. Like `Marker`, the `indicator` pill shows
the formatted `value`, never the `label`.

## `Marker`

A vertical line at an x position (a time, a distance, a lap boundary).

<ChartExample name="charts-annotation-marker" height={240}>
  <ChartsAnnotationMarker />
</ChartExample>

| Prop        | Type                   | Default | Purpose                                                                                     |
| ----------- | ---------------------- | ------- | ------------------------------------------------------------------------------------------- |
| `at`        | `number`               | —       | x position in axis units — epoch ms on a time axis, the value on a value axis.              |
| `label`     | `string \| false`      | auto    | Chip label. Omit ⇒ auto-label with the shared x formatter; `false`/`''` ⇒ no chip.          |
| `indicator` | `boolean`              | `false` | Also pin `at` to the **x-axis** as an on-axis pill (the axis-edge counterpart of the chip). |
| `lineWidth` | `number`               | `1`     | Stroke width in px. Wins over the theme role's / register's `lineWidth`.                    |
| `onChange`  | `(at: number) => void` | —       | Editable: drag the line to report a new `at` (controlled — wire it back).                   |

Plus the shared interaction props. Note the [indicator law](./the-annotation-model.mdx#pills-vs-flags--the-indicator-law):
the `indicator` pill always shows the formatted `at`, never the custom `label`
(which stays the near-line chip).

## Colour: `role`

All three take an optional **`role`** — a name into the theme's
`annotation.roles` map — to restyle that mark (any of `color`, `fillOpacity`,
`dash`, `lineWidth` and `depth`) while staying in the annotation register.
The built-in themes ship `wash` (quiet, behind data) and `argument` (stays
legible at rest). See
[Roles within the register](./the-annotation-model.mdx#roles-within-the-register).
There is no per-mark colour prop; the theme owns the palette.

## Stronger reference lines

An inert mark (`selectable={false}`) always draws at depth level 3, which is
`depth[2]` of the theme's `annotation.depth` ramp — `0.4` by default. To draw
one reference line near full strength, don't raise `depth[2]`: that dims or
lifts every annotation on every chart. Give the line a **role** with its own
ramp instead. An inert mark reads the third value of its role's `depth`, and
every mark without that role keeps the register's ramp.

The built-in themes already ship one: `argument` rests at `0.85`.

```tsx
<Baseline value={target} label="target" role="argument" selectable={false} />
```

Or define your own role, with exactly the strength you want:

```tsx
const theme: ChartTheme = {
  ...defaultTheme,
  annotation: {
    ...defaultTheme.annotation!,
    roles: {
      ...defaultTheme.annotation!.roles,
      reference: { depth: [1, 0.85, 0.8] },
    },
  },
};
// …
<Baseline value={limit} role="reference" selectable={false} />;
```

That baseline draws at `0.8`; a plain inert baseline beside it still draws at
`0.4`. Hover and selection don't apply to an inert mark, so only the role's
third value matters for it (the first two apply if a selectable mark uses the
same role).

**How opacity combines with depth.** The depth value is the line's SVG
`opacity`, and there is no per-mark opacity prop. Any other opacity
multiplies with it: an alpha in the colour (`rgba(…)` or `#rrggbbaa`) or a CSS
`opacity` on an element around the chart. A colour at alpha `0.6` on an inert
line at depth `0.4` draws at `0.6 × 0.4 = 0.24`. So keep the colour opaque and
set the strength in the role's `depth`. Depth dims only the line: the label
chip's text is drawn in the colour as given.

A baseline casts no guide on other rows. A marker's guides on other rows are
drawn the same faint dashed way for every mark, in the register colour, so a
strong role does not change them.

## Line width

`Baseline` and `Marker` draw a 1px line by default. Set `lineWidth` (px) on the
mark, or `lineWidth` on a theme role (`annotation.roles[role].lineWidth`) or on
the whole register (`annotation.lineWidth`). The mark's prop wins over the
role, and the role wins over the register. The invisible grab area stays at
least as wide as the line. Region edges, zone boundaries and the faint guides a
mark casts on other rows stay 1px.

```tsx
<Baseline value={200} label="1px" />
<Baseline value={180} label="3px" lineWidth={3} />
```

## Auto-labels and suppression

All three share the same `label` convention:

- **Omit `label`** → an automatic label from the shared axis formatter (a
  region shows `from–to`, a marker its `at`, a baseline its `value`).
- **`label="text"`** → your text on the near-line chip.
- **`label={false}`** (or `''`) → **no chip at all** — for an inert
  background band or context line where the raw axis value would be noise.
