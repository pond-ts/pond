# Reducer Reference

pond-ts ships 15 built-in reducers, plus percentile patterns (`p50`,
`p95`, …) and top-N-by-frequency patterns (`top3`, `top10`, …). Every
built-in works in `aggregate()`, `reduce()`, `rolling()`, and
`collapse()`. The two array-producing reducers (`unique` and `top(n)`)
also slot into
[`arrayAggregate()`](../advanced/arrays#per-event-reduction-arrayaggregate).

## Choosing a reducer

Quick guide — skip ahead to the detailed sections when you know what
you want:

| You want…                                                | Reducer                                               |
| -------------------------------------------------------- | ----------------------------------------------------- |
| Running total or counter                                 | [`sum`](#sum), [`count`](#count)                      |
| Central tendency                                         | [`avg`](#avg), [`median`](#median)                    |
| Spread / volatility                                      | [`stdev`](#stdev), [`difference`](#difference)        |
| Extremes                                                 | [`min`](#min), [`max`](#max)                          |
| Tail behavior                                            | [`p95`, `p99`, `p99.9`](#percentiles-p0-through-p100) |
| First or last seen                                       | [`first`](#first), [`last`](#last)                    |
| Constant metadata column (e.g. `host` after bucketing)   | [`keep`](#keep)                                       |
| Distinct values in a bucket                              | [`unique`](#unique)                                   |
| Most-frequent values                                     | [`top(n)`](#topn--topnumber)                          |
| All values (with duplicates, for downstream computation) | [`samples`](#samples)                                 |
| None of the above                                        | [Custom reducer function](#custom-reducers)           |

Pandas analogues in order: `.sum()`, `.count()`, `.mean()`,
`.median()`, `.std()`, `.max() − .min()`, `.min()`, `.max()`,
`.quantile(0.95)`, `.first()`, `.last()`, a value that matches
`.nunique() == 1`, `.unique()`, `.value_counts().head(n)`, and any
lambda you want.

## Type narrowing on `reduce(mapping)`

`TimeSeries.reduce(mapping)` narrows each output field to the reducer's actual value type —
no `as` casts at the call site:

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
const result = series.reduce({
  cpu: 'avg', //   -> number | undefined
  latency: 'p95', //   -> number | undefined
  host: 'unique', //   -> ReadonlyArray<string> | undefined   (source: kind 'string')
  values: 'unique', //   -> ReadonlyArray<number> | undefined   (source: kind 'number')
  paths: 'top3', //   -> ReadonlyArray<string> | undefined
  status: 'last', //   -> string | undefined   (source column kind)
});

const avgCpu: number | undefined = result.cpu;
const hosts: ReadonlyArray<string> | undefined = result.host;
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Scalar, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let series = TimeSeries::new(
        "requests",
        vec![0, 1_000, 2_000, 3_000, 4_000],
        vec![
            Column::required("cpu", vec![0.2, 0.4, 0.6, 0.9, 0.5]),
            Column::required("latency", vec![120.0, 80.0, 200.0, 90.0, 60.0]),
            Column::required("host", vec!["b", "a", "b", "c", "a"]),
            Column::required("values", vec![3.0, 1.0, 3.0, 2.0, 1.0]),
            Column::required("paths", vec!["/a", "/b", "/a", "/c", "/a"]),
            Column::required("status", vec!["ok", "ok", "err", "ok", "slow"]),
        ],
    )?;

    let result = series.reduce(&[
        Agg::of("cpu", Reducer::Avg),
        Agg::of("latency", Reducer::Percentile(95.0)),
        Agg::of("host", Reducer::Unique),
        Agg::of("values", Reducer::Unique),
        Agg::of("paths", Reducer::Top(3)),
        Agg::of("status", Reducer::Last),
    ])?;

    // Read each output with the method for its kind.
    let avg_cpu: Option<f64> = result.number("cpu")?;
    assert_eq!(avg_cpu, Some(0.52));
    assert_eq!(result.number("latency")?, Some(184.0));
    let hosts: Option<&[Scalar]> = result.array("host")?;
    assert_eq!(hosts.unwrap(), &[Scalar::from("a"), "b".into(), "c".into()]);
    let values = result.array("values")?.unwrap();
    assert_eq!(values, &[Scalar::from(1.0), 2.0.into(), 3.0.into()]);
    let paths = result.array("paths")?.unwrap();
    assert_eq!(paths, &[Scalar::from("/a"), "/b".into(), "/c".into()]);
    assert_eq!(result.string("status")?, Some("slow"));

    // The wrong kind is an error when the code runs.
    assert!(result.number("host").is_err());
    Ok(())
}
```

Rust does not track column kinds in its types, so each output is read with the method for its kind (`number`, `string`, `array`, …), which checks it when the code runs. `unique` and `top(n)` give a list (`&[Scalar]`) on any column kind.

</TabItem>
</Tabs>

**Array-output reducers thread source column kind through.** `'unique'` and any
`top${number}` on a `kind: 'string'` column narrow to `ReadonlyArray<string>`, on a
`kind: 'number'` column to `ReadonlyArray<number>`, on a `kind: 'boolean'` column to
`ReadonlyArray<boolean>`. Array-kind source columns fall back to the wide
`ReadonlyArray<ScalarValue>` union because tracking element kind on an array column is out
of scope for the schema.

Custom reducer functions and `AggregateOutputSpec` entries (`{ from, using, kind? }`) fall
back to `ColumnValue | undefined` because their output kind is set at runtime and the type
system can't see through it.

## Numeric reducers

These operate on numeric values only. Non-numeric and `undefined` values are filtered out
before the reducer runs.

### `sum`

Total of all numeric values in the bucket.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
series.aggregate(Sequence.every('5m'), { requests: 'sum' });
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let min = 60_000;
    // Nothing between 5 and 10 minutes.
    let series = TimeSeries::new(
        "web",
        vec![0, min, 2 * min, 10 * min],
        vec![Column::required("requests", vec![10.0, 20.0, 30.0, 5.0])],
    )?;

    let out = series.aggregate(
        &Sequence::every("5m")?,
        &[
            Agg::of("requests", Reducer::Sum),
            Agg::new("n", "requests", Reducer::Count),
            Agg::new("avg", "requests", Reducer::Avg),
        ],
    )?;
    let sum: Vec<_> = out.column("requests")?.numbers()?.iter().collect();
    let n: Vec<_> = out.column("n")?.numbers()?.iter().collect();
    let avg: Vec<_> = out.column("avg")?.numbers()?.iter().collect();
    assert_eq!(sum, [Some(60.0), Some(0.0), Some(5.0)]); // the empty bucket sums to 0
    assert_eq!(n, [Some(3.0), Some(0.0), Some(1.0)]); // and counts 0
    assert_eq!(avg, [Some(20.0), None, Some(5.0)]); // but has no average
    Ok(())
}
```

This covers `count` below too.

</TabItem>
</Tabs>

Returns `0` for an empty bucket (there are zero values to sum).

### `avg`

Arithmetic mean of numeric values.

```ts
series.reduce('cpu', 'avg');
```

Returns `undefined` for an empty bucket.

### `min`

Smallest numeric value.

```ts
series.aggregate(Sequence.every('1h'), { temperature: 'min' });
```

Returns `undefined` for an empty bucket.

### `max`

Largest numeric value.

```ts
series.aggregate(Sequence.every('1h'), { temperature: 'max' });
```

Returns `undefined` for an empty bucket.

### `median`

Middle value of the sorted numeric values. For even-length sets, linearly interpolates
between the two middle values (equivalent to `p50`).

```ts
series.reduce('latency', 'median');
```

Returns `undefined` for an empty bucket.

### `stdev`

Population standard deviation. Measures how spread out the values are around the mean.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
series.aggregate(Sequence.every('10m'), { latency: 'stdev' });
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Column, Reducer, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let series = TimeSeries::new(
        "web",
        vec![0, 1_000, 2_000, 3_000],
        vec![Column::required(
            "latency",
            vec![100.0, 140.0, 120.0, 130.0],
        )],
    )?;
    let r = |reducer| series.reduce_number("latency", reducer);

    assert_eq!(r(Reducer::Avg)?, Some(122.5));
    assert_eq!(r(Reducer::Min)?, Some(100.0));
    assert_eq!(r(Reducer::Max)?, Some(140.0));
    assert_eq!(r(Reducer::Median)?, Some(125.0)); // between 120 and 130
    assert_eq!(r(Reducer::Stdev)?, Some(14.79019945774904)); // divides by n
    assert_eq!(r(Reducer::Difference)?, Some(40.0)); // max - min

    let flat = TimeSeries::new("f", vec![0, 1], vec![Column::required("v", vec![5.0, 5.0])])?;
    assert_eq!(flat.reduce_number("v", Reducer::Stdev)?, Some(0.0));
    Ok(())
}
```

This covers `avg`, `min`, `max`, `median` and `difference` too.

</TabItem>
</Tabs>

Returns `0` when all values are identical. Returns `undefined` for an empty bucket.

### `difference`

Range within the bucket: `max - min`. Useful for measuring volatility or stability within
a time window.

```ts
series.aggregate(Sequence.every('10m'), { temperature: 'difference' });
```

Returns `0` for a single value. Returns `undefined` for an empty bucket.

### `count`

Number of defined (non-`undefined`) values. Works on any column type, not just numeric.

```ts
series.aggregate(Sequence.every('1h'), { errors: 'count' });
```

Returns `0` for an empty bucket.

### Percentiles: `p0` through `p100`

The `p` prefix followed by a number (0--100) computes that percentile with linear
interpolation between adjacent ranks.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
series.aggregate(Sequence.every('5m'), {
  p50: { from: 'latency', using: 'p50', kind: 'number' },
  p95: { from: 'latency', using: 'p95', kind: 'number' },
  p99: { from: 'latency', using: 'p99', kind: 'number' },
});
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let min = 60_000;
    let series = TimeSeries::new(
        "web",
        vec![0, min, 2 * min, 10 * min],
        vec![Column::required(
            "latency",
            vec![100.0, 140.0, 120.0, 130.0],
        )],
    )?;

    let out = series.aggregate(
        &Sequence::every("5m")?,
        &[
            Agg::new("p50", "latency", Reducer::Percentile(50.0)),
            Agg::new("p95", "latency", Reducer::Percentile(95.0)),
            Agg::new("p99", "latency", Reducer::Percentile(99.0)),
        ],
    )?;
    let p95: Vec<_> = out.column("p95")?.numbers()?.iter().collect();
    assert_eq!(p95, [Some(138.0), None, Some(130.0)]); // the empty bucket: a gap

    // One column, and pond-ts's names parsed into a Reducer.
    assert_eq!(
        series.reduce_number("latency", Reducer::parse("p95")?)?,
        Some(138.5)
    );
    assert_eq!(
        series.reduce_number("latency", Reducer::parse("p99.9")?)?,
        Some(139.97)
    );
    assert_eq!(
        series.reduce_number("latency", Reducer::Percentile(0.0))?,
        Some(100.0)
    );
    Ok(())
}
```

`Reducer::Percentile(q)` takes `q` from 0 to 100. `Reducer::parse` reads pond-ts's names (`"p95"`, `"top3"`, …). This covers the one-column form below too.

</TabItem>
</Tabs>

Shorthand when aggregating a single column:

```ts
series.reduce('latency', 'p95');
```

Fractional percentiles are supported: `'p99.9'`.

`p0` returns the minimum, `p50` is equivalent to `median`, `p100` returns the maximum.

Returns `undefined` for an empty bucket.

## Any-type reducers

These work on values of any column kind (number, string, boolean).

### `first`

First non-`undefined` value in the bucket (by event order).

```ts
series.aggregate(Sequence.every('1h'), { status: 'first' });
```

Returns `undefined` for an empty bucket.

### `last`

Last non-`undefined` value in the bucket.

```ts
series.aggregate(Sequence.every('1h'), { status: 'last' });
```

Returns `undefined` for an empty bucket.

### `keep`

Returns the value if every value in the bucket is identical; `undefined` otherwise.
Useful for preserving constant metadata columns (like `host`) through aggregation.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
const hourly = series.aggregate(Sequence.every('1h'), {
  cpu: 'avg',
  host: 'keep',
});
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let half_hour = 1_800_000;
    let series = TimeSeries::new(
        "cpu",
        vec![0, half_hour, 2 * half_hour, 3 * half_hour],
        vec![
            Column::required("cpu", vec![0.2, 0.4, 0.6, 0.8]),
            Column::required("host", vec!["a", "a", "a", "b"]),
            Column::required("status", vec!["ok", "slow", "ok", "err"]),
        ],
    )?;

    let hourly = series.aggregate(
        &Sequence::every("1h")?,
        &[
            Agg::of("cpu", Reducer::Avg),
            Agg::of("host", Reducer::Keep),
            Agg::new("first", "status", Reducer::First),
            Agg::new("last", "status", Reducer::Last),
        ],
    )?;
    let host: Vec<_> = hourly.column("host")?.strings()?.iter().collect();
    assert_eq!(host, [Some("a"), None]); // the second hour mixes a and b
    let first: Vec<_> = hourly.column("first")?.strings()?.iter().collect();
    let last: Vec<_> = hourly.column("last")?.strings()?.iter().collect();
    assert_eq!(first, [Some("ok"), Some("ok")]);
    assert_eq!(last, [Some("slow"), Some("err")]);
    Ok(())
}
```

This covers `first` and `last` above too.

</TabItem>
</Tabs>

If the series was already partitioned by `groupBy('host')`, `keep` will always return the
host name since all events in each group share the same value.

Returns `undefined` for an empty bucket or mixed values.

## Array-producing reducers

These two reducers output an array column (`kind: 'array'`) instead of a scalar. They
drive most of the tagging / distinct-value workflows — see the
[Array Columns guide](../advanced/arrays) for the full treatment.

### `unique`

Distinct non-`undefined` values, sorted. Works on any column kind.

**On a scalar source column.** Produces one array per bucket containing every distinct
value seen, sorted deterministically (numbers &lt; strings &lt; booleans, JS default within
a kind).

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
const hosts = new TimeSeries({
  name: 'hosts',
  schema: [
    { name: 'time', kind: 'time' },
    { name: 'host', kind: 'string' },
  ] as const,
  rows: [
    // bucket [0s, 3s) ─────────────────
    [0, 'api-1'],
    [1000, 'api-1'],
    [2000, 'api-2'],
    // bucket [3s, 6s) ─────────────────
    [3500, 'api-3'],
    [4000, 'api-1'],
    [5500, 'api-1'],
  ],
});

const agg = hosts.aggregate(Sequence.every('3s'), {
  host: 'unique', // 'string' -> 'array'
});

// agg.at(0)!.get('host')  =>  ['api-1', 'api-2']
// agg.at(1)!.get('host')  =>  ['api-1', 'api-3']
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Scalar, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let hosts = TimeSeries::new(
        "hosts",
        vec![0, 1_000, 2_000, 3_500, 4_000, 5_500],
        vec![Column::required(
            "host",
            vec!["api-1", "api-1", "api-2", "api-3", "api-1", "api-1"],
        )],
    )?;

    let agg = hosts.aggregate(&Sequence::every("3s")?, &[Agg::of("host", Reducer::Unique)])?;
    let lists = agg.column("host")?.arrays()?; // a text column in, a list column out
    let s = |v: &str| Scalar::from(v);
    assert_eq!(lists.get(0).unwrap(), &[s("api-1"), s("api-2")]);
    assert_eq!(lists.get(1).unwrap(), &[s("api-1"), s("api-3")]);
    Ok(())
}
```

</TabItem>
</Tabs>

**On an array-kind source column.** `unique` flattens one level and takes the **set union**
of elements across every array in the bucket.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
const tagged = new TimeSeries({
  name: 'tagged',
  schema: [
    { name: 'time', kind: 'time' },
    { name: 'tags', kind: 'array' },

    // bucket [0s, 3s) ─────────────────
    [0, ['5xx', 'timeout']],
    [500, ['5xx']],

    [3500, ['timeout']],

});

const agg = tagged.aggregate(Sequence.every('3s'), {
  tags: 'unique',
});

// agg.at(0)!.get('tags')  =>  ['5xx', 'retry', 'timeout']
//   union of ['5xx','timeout'] + ['5xx'] + ['retry'] = {5xx, timeout, retry}
// agg.at(1)!.get('tags')  =>  ['timeout']
```

</TabItem>
<TabItem value="rust" label="Rust">


Returns `[]` for an empty bucket.

### `top(n)` / `` `top${number}` ``

Top N values by frequency, sorted by count descending. Ties break by scalar order
(numbers &lt; strings &lt; booleans, JS default within a kind). If N exceeds the unique
count, all unique values are returned. Parsed from the string pattern
`` `top${number}` `` (like `p${number}`); the `top(n)` helper returns the typed string
literal — either form is accepted.

**On a scalar source column.** Counts occurrences in the bucket and keeps the most
frequent N.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
import { top } from 'pond-ts';

const hosts = new TimeSeries({
  name: 'hosts',
  schema: [
    { name: 'time', kind: 'time' },
    { name: 'host', kind: 'string' },
  ] as const,
  rows: [
    // bucket [0s, 3s) ─────────────────
    [0, 'api-1'],
    [500, 'api-2'],
    [1000, 'api-1'],
    [1500, 'api-3'],
    [2500, 'api-1'],
    // bucket [3s, 6s) ─────────────────
    [3500, 'api-4'],
    [4000, 'api-4'],
    [4500, 'api-2'],
  ],
});

const agg = hosts.aggregate(Sequence.every('3s'), {
  host: top(2), // 'string' -> 'array', top 2 most frequent
});

// agg.at(0)!.get('host')  =>  ['api-1', 'api-2']
//   counts: api-1=3, api-2=1, api-3=1. api-1 wins outright;
//   api-2 beats api-3 on the tie-break (scalar order).
// agg.at(1)!.get('host')  =>  ['api-4', 'api-2']
//   counts: api-4=2, api-2=1.
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Scalar, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let hosts = TimeSeries::new(
        "hosts",
        vec![0, 500, 1_000, 1_500, 2_500, 3_500, 4_000, 4_500],
        vec![Column::required(
            "host",
            vec![
                "api-1", "api-2", "api-1", "api-3", "api-1", "api-4", "api-4", "api-2",
            ],
        )],
    )?;

    let agg = hosts.aggregate(&Sequence::every("3s")?, &[Agg::of("host", Reducer::Top(2))])?;
    let lists = agg.column("host")?.arrays()?;
    let s = |v: &str| Scalar::from(v);
    // api-1 three times; api-2 beats api-3 on the tie-break.
    assert_eq!(lists.get(0).unwrap(), &[s("api-1"), s("api-2")]);
    assert_eq!(lists.get(1).unwrap(), &[s("api-4"), s("api-2")]);

    // The string form parses to the same reducer.
    assert_eq!(Reducer::parse("top2")?, Reducer::Top(2));
    assert!(Reducer::parse("top0").is_err());
    Ok(())
}
```

`Reducer::Top(n)` is pond-ts's `top(n)`; `Reducer::parse("top2")` gives the same.

</TabItem>
</Tabs>

The string form is interchangeable: `{ host: 'top2' }` does the same thing.

**On an array-kind source column.** Counts **elements across every array** in the bucket,
not the arrays themselves.

<TabItem value="ts" label="TypeScript" default>


Invalid names (`'top0'`, `'top-1'`) throw at resolve time.

Rolling-window complexity is O(1) per add/remove (count map); final sort on snapshot is
O(k log k) where k is the distinct value count.

Returns `[]` for an empty bucket.

### `samples`

All defined values in the bucket, returned as an array in arrival order. **Duplicates are
preserved** (this is what distinguishes `samples` from `unique` and `top${N}`). Reach for
`samples` when a downstream computation needs the raw value list — anomaly density
against an externally-computed baseline, custom thresholding, histogramming, or feeding
into a non-pond pipeline.

```rust
use pond_rs::{Agg, Column, Reducer, Scalar, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let cpu = TimeSeries::new(
        "cpu",
        vec![0, 1_000, 2_000, 3_500, 4_000],
        vec![Column::required("cpu", vec![0.4, 0.5, 0.4, 0.6, 0.7])],
    )?;
    let every_3s = Sequence::every("3s")?;

    let agg = cpu.aggregate(&every_3s, &[Agg::new("vals", "cpu", Reducer::Samples)])?;
    let vals = agg.column("vals")?.arrays()?;
    let n = |v: f64| Scalar::from(v);
    assert_eq!(vals.get(0).unwrap(), &[n(0.4), n(0.5), n(0.4)]); // duplicates kept
    assert_eq!(vals.get(1).unwrap(), &[n(0.6), n(0.7)]);

    // On a list column, the lists are joined first.
    let s = |v: &str| Scalar::from(v);
    let tagged = TimeSeries::new(
        "tagged",
        vec![0, 500, 1_000],
        vec![Column::required(
            "tags",
            vec![
                vec![s("5xx"), s("timeout")],
                vec![s("5xx")],
                vec![s("retry")],
            ],
        )],
    )?;
    let flat = tagged.aggregate(&every_3s, &[Agg::new("flat", "tags", Reducer::Samples)])?;
    let lists = flat.column("flat")?.arrays()?;
    assert_eq!(
        lists.get(0).unwrap(),
        &[s("5xx"), s("timeout"), s("5xx"), s("retry")]
    );
    Ok(())
}
```

Like `unique`, `samples` flattens one level on array-kind source columns:

```ts
tagged.aggregate(Sequence.every('3s'), {
  flat: { from: 'tags', using: 'samples' },
});
// bucket [0s, 3s) — sources [['5xx','timeout'], ['5xx'], ['retry']]
//   .get('flat')  =>  ['5xx', 'timeout', '5xx', 'retry']   — flat, ordered, with duplicates
```

**Use on bounded windows.** Memory is O(window size); per-event cost is O(1) `add` and
O(1) `remove` (Map-keyed by event index); `snapshot` is O(N) for the array copy. For
unbounded `reduce(mapping)` on a large series, expect to allocate one array of every
defined value — `count` or a custom function is usually cheaper if you don't actually
need the values.

Returns `[]` for an empty bucket.

## Custom reducers

Supply a function wherever a built-in name is accepted. The function receives all values
in the bucket (including `undefined` entries) and returns a scalar.

```ts
series.aggregate(Sequence.every('10m'), {
  value: (values) => {
    const nums = values.filter((v): v is number => typeof v === 'number');
    return nums.length === 0 ? undefined : nums.reduce((a, b) => a + b, 0);
  },
});
```

pond-rs has no custom reducer functions yet. Use a built-in, or
`Reducer::Samples` to get the values as a list and work on them yourself.

Custom reducers work in `aggregate()`, `reduce()`, `rolling()`, `collapse()`, and (since
v0.14.1) every live counterpart — `live.aggregate()`, `live.rolling()`, and
`partitionBy(c).rolling(...)`.

:::caution[Performance characteristic on live]

Built-in reducers maintain incremental state — `add`/`remove`/`snapshot` are each O(1).
Custom functions don't have that machinery, so the live adapter buffers values and re-runs
the function over the entire current window at each `snapshot()` call. Per-event cost is
still O(1) for state maintenance, but **`snapshot()` is O(window size)** — the function
re-runs every time the accumulator emits.

For high-throughput live use, prefer:

- a built-in reducer (`avg`, `p95`, `stdev`, ...) when one fits, or
- `'samples'` to collapse the window to a value list once, then run your custom logic on
  the consumer side after the snapshot has fired.

Custom-function reducers shine on low-rate streams where convenience matters more than
per-snapshot cost — debug aggregations, prototype pipelines, dashboards under
~1k events/sec.

:::

## Empty-bucket behavior

| Reducer      | Empty bucket |
| ------------ | ------------ |
| `count`      | `0`          |
| `sum`        | `0`          |
| `avg`        | `undefined`  |
| `min`        | `undefined`  |
| `max`        | `undefined`  |
| `median`     | `undefined`  |
| `stdev`      | `undefined`  |
| `difference` | `undefined`  |
| `first`      | `undefined`  |
| `last`       | `undefined`  |
| `keep`       | `undefined`  |
| `p50`...     | `undefined`  |
| `unique`     | `[]`         |
| `top3`...    | `[]`         |
| `samples`    | `[]`         |

### Non-finite results

A reducer never answers `NaN`, `Infinity` or `-Infinity`. A result that would be
non-finite — a `sum` or `avg` whose arithmetic overflows past
`Number.MAX_VALUE`, or a custom reducer returning `Infinity` — is `undefined`
(missing), the same as an empty bucket of `avg`. That holds for `reduce()`,
`aggregate()`, `rolling()` and the live accumulators alike: a non-finite number
in a number column means missing. (Non-finite _inputs_ cannot occur — no number
column holds one.)

A running window keeps its sum incrementally, so once a window's `sum` has
overflowed it stays `Infinity` internally even after the large values leave
the window, and those rows read missing too.

## Rolling window behavior

All built-in reducers work with `rolling()`. Most use O(1) incremental add/remove:

| Reducer                             | Rolling complexity                          |
| ----------------------------------- | ------------------------------------------- |
| `sum`, `avg`, `count`, `stdev`      | O(1) per event                              |
| `min`, `max`                        | O(1) amortized (monotone deque)             |
| `first`, `last`                     | O(1) amortized                              |
| `median`, percentiles, `difference` | O(N) per event (sorted array insert/remove) |
| `keep`, `unique`                    | O(1) per event (value count map)            |
| `top(n)`                            | O(1) add/remove; O(k log k) snapshot sort   |
| `samples`                           | O(1) add/remove; O(N) snapshot              |
| Custom function                     | O(1) add/remove; O(N) snapshot              |

For typical rolling windows (tens to hundreds of events), the sorted array approach
is fast enough. For very large windows with median/percentile, consider a custom reducer
— but note that custom functions on live also pay O(N) per snapshot (the function re-runs
over the current window each emit). See [Custom reducers](#custom-reducers) for the
trade-off.

## Multi-window rolling: merged output schema

Multi-window rolling
([`live.rolling({ '1m': m1, '200ms': m2 }, opts)`](./rolling#multi-window))
emits one merged event per trigger fire with all windows' columns
concatenated into one record. Two rules govern the merged output
schema:

- **Output column names must be unique across all windows.**
  `{ '1m': { cpu_avg: 'avg' }, '5m': { cpu_avg: 'avg' } }` is
  rejected at construction. Reuse implies ambiguity at the
  merged-record level — rename one of the columns
  (`{ '5m': { cpu_avg_5m: { from: 'cpu', using: 'avg' } } }`) or
  drop the duplicating window.
- **Per-window kind narrowing follows the same dispatch as
  single-window rolling.** Each entry's `from` / `using` (or the
  AggregateMap shorthand `cpu: 'avg'`) resolves to a column kind
  using the same `OutputSpecKind` rules as `aggregate` and
  `rolling`. The merged schema is the union of all windows'
  per-column ColumnDefs.

Per-event reducer cost is unchanged from the single-window case —
each window's reducers update incrementally per source event. The
shared work is the per-event ingest pipeline (one routing pass
instead of N), which compounds at higher window counts. See
[Rolling → Multi-window rolling → Performance](./rolling#multi-window)
for the bench table.
