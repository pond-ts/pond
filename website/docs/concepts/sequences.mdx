# Sequences

A `Sequence` defines a **grid over the timeline** — a set of equally
or calendar-spaced boundaries that `aggregate`, `align`, and clock
triggers consume to bucket or sample events.

A sequence is a _grid definition_, not a finite bucket list. By
default it extends infinitely in both directions, anchored at the
Unix epoch. Operators that consume a sequence either intersect it
with the data (`aggregate(seq, mapping)`) or, in TypeScript, with an
explicit range to produce a finite slice.

<SequenceGrid />

## `Sequence.every(duration)` — fixed-step

Equally-spaced boundaries every `duration` milliseconds.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
import { Sequence } from 'pond-ts';

const minutely = Sequence.every('1m');
const second = Sequence.every('1s');
const tick = Sequence.every('200ms');
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::Sequence;

fn main() -> Result<(), pond_rs::PondError> {
    let minutely = Sequence::every("1m")?;
    let _second = Sequence::every("1s")?;
    let _tick = Sequence::every_ms(200)?; // or a plain millisecond number
    // The buckets overlapping a span, as begin and end lists.
    let b = minutely.buckets_overlapping(0, 150_000)?;
    assert_eq!(b.begin, [0, 60_000, 120_000]);
    assert!(Sequence::every("1M").is_err()); // a month is not a duration
    Ok(())
}
```

</TabItem>
<TabItem value="python" label="Python">

```python
from datetime import timedelta

import pond

minutely = pond.Sequence.every("1m")
second = pond.Sequence.every("1s")
tick = pond.Sequence.every(timedelta(milliseconds=200))  # or a timedelta
# The buckets overlapping a span, as (begin, end) pairs.
assert minutely.buckets(0, 150_000) == [(0, 60_000), (60_000, 120_000), (120_000, 180_000)]
```

</TabItem>
</Tabs>

`duration` accepts the standard duration string format
(`ms` / `s` / `m` / `h` / `d` suffixes) or a plain millisecond number.
The step is millisecond-exact regardless of calendar boundaries —
`Sequence.every('1d')` produces 86,400,000-ms-spaced boundaries, not
local-calendar days.

### Anchoring

By default a fixed-step sequence is anchored at Unix epoch (`0`),
which means independently-created sequences with the same step align
exactly. Override with the `anchor` option when you need a different
phase:

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
Sequence.every('30s', { anchor: 5_000 });
// boundaries at 5_000, 35_000, 65_000, … instead of 0, 30_000, 60_000
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::Sequence;

fn main() -> Result<(), pond_rs::PondError> {
    let seq = Sequence::every("30s")?.with_anchor(5_000);
    // Boundaries at 5_000, 35_000, 65_000, … instead of 0, 30_000, 60_000.
    assert_eq!(seq.buckets_overlapping(10_000, 40_000)?.begin, [5_000, 35_000]);
    Ok(())
}
```

</TabItem>
<TabItem value="python" label="Python">

```python
import pond

seq = pond.Sequence.every("30s", anchor=5_000)
# Boundaries at 5_000, 35_000, 65_000, … instead of 0, 30_000, 60_000.
assert seq.buckets(10_000, 40_000) == [(5_000, 35_000), (35_000, 65_000)]
```

</TabItem>
</Tabs>

The anchor is a `number | Date`; sequences with the same step but
different anchors produce different bucket boundaries and will not
align across operators.

### Convenience aliases

```ts
Sequence.hourly(); // = Sequence.every('1h')
Sequence.hourly({ anchor: 1800_000 });
Sequence.daily(); // = Sequence.every('1d')
Sequence.daily({ anchor: 5 * 3600_000 }); // anchor at 05:00 UTC
```

TypeScript only: in Rust and Python write `every("1h")` / `every("1d")`.
Same shape as `Sequence.every`, just named for the common cases.
Note that `daily()` here is **fixed-step** (86,400,000 ms exactly,
no DST awareness) — for local-calendar daily boundaries reach for
[`Sequence.calendar('day', { timeZone })`](#sequencecalendarunit-options--calendar-aligned).

## `Sequence.calendar(unit, options)` — calendar-aligned

Boundaries that snap to local-calendar units (day / week / month /
quarter / year) in a chosen time zone. Use these when calendar
boundaries matter — daily reports, monthly aggregates, weekday-vs-
weekend rollups.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
Sequence.calendar('day', { timeZone: 'America/New_York' });
Sequence.calendar('week', { timeZone: 'Europe/Madrid', weekStartsOn: 1 });
Sequence.calendar('month', { timeZone: 'UTC' });
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Sequence, parse_time};

fn main() -> Result<(), pond_rs::PondError> {
    let days = Sequence::calendar("day", "America/New_York")?;
    let _weeks = Sequence::calendar("week", "Europe/Madrid")?.with_week_start(1)?; // Monday
    let _months = Sequence::calendar("month", "UTC")?;

    // The day the clocks went forward in New York is 23 hours long.
    let b = days.buckets_overlapping(parse_time("2025-03-09T12:00:00Z")?, parse_time("2025-03-09T12:00:00Z")?)?;
    assert_eq!(b.end[0] - b.begin[0], 23 * 3_600_000);
    assert!(Sequence::calendar("day", "Mars/Olympus").is_err()); // an unknown zone
    Ok(())
}
```

</TabItem>
<TabItem value="python" label="Python">

```python
import pond

days = pond.Sequence.calendar("day", "America/New_York")
weeks = pond.Sequence.calendar("week", "Europe/Madrid", week_starts_on=1)  # Monday
months = pond.Sequence.calendar("month", "UTC")

# The day the clocks went forward in New York is 23 hours long.
t = pond.parse_time("2025-03-09T12:00:00Z")
[(begin, end)] = days.buckets(t, t)
assert end - begin == 23 * 3_600_000
try:
    pond.Sequence.calendar("day", "Mars/Olympus")  # an unknown zone
    raise AssertionError("expected an error")
except pond.PondError:
    pass
```

</TabItem>
</Tabs>

A month is not a duration, so `Sequence.every('1M')` **throws** — reach for
`Sequence.calendar('month', …)` instead.

`timeZone` defaults to `'UTC'`; pass a zone because calendar boundaries
are not millisecond-fixed — a "day" in `America/New_York` is 24 hours
except on DST transition days, where it's 23 or 25. Boundaries are
computed by [`TimeZone`](#timezone), which is IANA-correct (Temporal
underneath) and caches each zone's offset transitions, so bucketing a
long series costs the same as fixed-step arithmetic. An unknown unit or
zone throws `RangeError` at construction (an `Err` in Rust, a
`pond.PondError` in Python). Rust and Python carry their own copy of the
time-zone database (`pond_rs::tzdb_version()` in Rust and
`pond.tzdb_version` in Python say which).

### `TimeZone`

_TypeScript only._ The zone primitive `Sequence.calendar` buckets with,
exported for callers who need the same answers directly — a chart axis placing ticks, a report
labelling a bucket in the zone it was cut in:

```ts
import { TimeZone } from 'pond-ts';

const tz = TimeZone.of('Australia/Sydney'); // interned; TimeZone.UTC, TimeZone.local()
tz.startOf('week', t, { weekStartsOn: 1 }); // first instant of the local week containing t
tz.next('month', t); // exclusive end of the local month containing t
tz.parts(t); // { year, month, day, hour, minute, second, millisecond, weekday }
tz.instant({ year: 2026, month: 4, day: 5, hour: 2, minute: 30 }); // wall clock → instant
tz.offsetAt(t); // ms east of UTC
tz.abbreviation(t, { locale: 'en-AU' }); // 'AEDT'
```

`instant()` resolves a repeated or skipped wall time the way Temporal
does (`disambiguation: 'compatible'` by default — earlier for a
fall-back, forward past the gap for a spring-forward; `'earlier'`,
`'later'` and `'reject'` are the alternatives). A `TimeZone` holds no
instant of its own: `Time`, `TimeRange` and `Interval` stay plain UTC
milliseconds, and the zone is a parameter to whatever interprets them.

### When calendar vs fixed-step matters

| Use calendar when…                           | Use fixed-step when…                            |
| -------------------------------------------- | ----------------------------------------------- |
| Bucket means a calendar day / month / etc.   | Bucket means N seconds / minutes / hours        |
| DST and varying month lengths matter         | DST and month variation are noise               |
| Reports align to local working hours         | Sampling cadence is independent of wall clock   |
| Cross-region comparisons need same wall hour | Cross-region comparisons need same elapsed time |

Calendar sequences are **rejected by some operators** that require
constant-step boundaries — notably clock-triggered live rolling
(`Trigger.clock(seq)` / `Trigger.every(duration)`). The boundary
indexing math assumes a constant step. See
[Triggering](/docs/live/triggering).

## `Sequence.kind()` — discriminator

```ts
seq.kind(); // 'fixed' | 'calendar' (TypeScript only)
```

Operators that need to know whether the boundaries are constant-step
read this. Most application code doesn't.

## Bounded vs unbounded

The `Sequence` types above are **unbounded** — they describe a grid
that extends in both directions. To work with a finite list of
buckets, either:

1. Pass an explicit range to the operator (`aggregate(seq, mapping, { range })`, TypeScript only; Rust and Python `aggregate` take no range)
2. Use `BoundedSequence` directly when the buckets are irregular

### `BoundedSequence`

_TypeScript only for now._ An explicit finite list of `Interval`s. Use
when the buckets are
**not** regular — business quarters, predefined report ranges,
boundaries supplied by an external system.

```ts
import { BoundedSequence, Interval } from 'pond-ts';

const parse = Date.parse;
const quarters = new BoundedSequence([
  new Interval({
    value: 'Q1',
    start: parse('2025-01-01'),
    end: parse('2025-04-01'),
  }),
  new Interval({
    value: 'Q2',
    start: parse('2025-04-01'),
    end: parse('2025-07-01'),
  }),
  new Interval({
    value: 'Q3',
    start: parse('2025-07-01'),
    end: parse('2025-10-01'),
  }),
  new Interval({
    value: 'Q4',
    start: parse('2025-10-01'),
    end: parse('2026-01-01'),
  }),
]);
```

The `index` value of each `Interval` becomes the bucket label in the
output — `cpu.aggregate(quarters, { cpu: 'avg' }).at(0).key().index()`
returns `'Q1'`. This is what the bucket round-trips through JSON as.

`aggregate` and `align` accept `Sequence | BoundedSequence`
interchangeably; downstream operators don't care which produced the
bucket.

## Half-open boundaries

Every sequence — fixed-step, calendar, or bounded — produces
**half-open `[begin, end)`** bucket extents. An event whose key
timestamp equals a boundary lands in the _later_ bucket, not the
earlier one.

<Tabs groupId="language" queryString>
<TabItem value="ts" label="TypeScript" default>

```ts
const seq = Sequence.every('1m');
// Boundary at t=60_000 belongs to bucket [60_000, 120_000), not [0, 60_000)
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust
use pond_rs::{Agg, Column, Reducer, Sequence, TimeSeries};

fn main() -> Result<(), pond_rs::PondError> {
    let s = TimeSeries::new("s", vec![30_000, 60_000], vec![Column::required("v", vec![1.0, 2.0])])?;
    let out = s.aggregate(&Sequence::every("1m")?, &[Agg::of("v", Reducer::Count)])?;
    // The row at 60_000 belongs to [60_000, 120_000), not [0, 60_000).
    assert_eq!(out.column("v")?.numbers()?.values(), &[1.0, 1.0]);
    Ok(())
}
```

</TabItem>
<TabItem value="python" label="Python">

```python
import pond

s = pond.TimeSeries({"time": [30_000, 60_000], "v": [1.0, 2.0]})
out = s.aggregate("1m", {"v": "count"})
# The row at 60_000 belongs to [60_000, 120_000), not [0, 60_000).
assert out.column("v") == [1.0, 1.0]
```

</TabItem>
</Tabs>

This is consistent across all temporal-relation operations
(`within`, `overlapping`, `trim`) and matters when event timestamps
land exactly on boundaries — typical for synthetic data, less so for
real telemetry.

## Where this shows up

- **Aggregation** — `series.aggregate(seq, mapping, { range? })`
  buckets events onto sequence boundaries; output is `Interval`-keyed.
  See [Aggregation](/docs/series/aggregation).
- **Alignment** — `series.align(seq, { method, sample })` produces
  one event per sequence point with values resampled from the source.
  See [Alignment](/docs/series/alignment).
- **Grid-form rolling** — `series.rolling(seq, window, mapping)`
  takes a sequence to define output cadence and a window for the
  reduction range. See [Rolling](/docs/series/rolling).
- **Clock triggers** — `Trigger.clock(seq)` and the
  `Trigger.every(duration)` sugar use a sequence to define the
  emission cadence of live rolling. Calendar sequences are rejected.
  See
  [Triggering](/docs/live/triggering).
- **`Interval` keys** — every operator that consumes a sequence
  produces `Interval`-keyed output. See [Temporal keys](./temporal-keys).
